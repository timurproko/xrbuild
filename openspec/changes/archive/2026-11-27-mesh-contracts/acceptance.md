# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Final meshes receive source confidence, support and age without changing the provider ABI or skeleton interaction.
- Mesh results and cached topology cannot cross a requested settings generation; saved, applied and drawing state stay distinct.
- Startup and reprepare expose bounded progress and hard preparation deadlines while input sessions keep running.
- Mesh descendants are contained from birth and teardown is verified on Stop, crash, supervisor loss and owner exit.
- Runtime resolution defaults to ~/.xrbuild, rejects unsafe or stale receipts and never installs or writes workspace files.
- Mesh selection and skeleton visibility stay independent, with legacy negotiation and excluded portable contexts retained.
