# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Provider selection saves silently with inline retry on failure; Record and routine source status or guidance are absent.
- Post-processing is entirely hidden without installed plugins and remains below the provider when plugins are present.
- Both adjustment groups use direct standard panel sections, retain every control and have independent secondary resets.
- Finished edits save and deliver without Apply, intermediate writes or routine Reload; failures retain values with retry.
- Revision conflicts preserve newer saved fields, and active live sessions retain exclusive profile application ownership.
- Recorder code and stored recordings remain intact but recording is unreachable from Hands pending future placement.
- Apps Input displays Hands while existing settings continue to persist the hand value.
