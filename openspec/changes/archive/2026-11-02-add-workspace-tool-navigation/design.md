## Decisions

1. Preserve the current worktree and all uncommitted diagnostic work. The operator explicitly approved implementing the stated menu UX in this task. No tracking changes or automatic stage advance.
2. Use optional integration-workspace `xrb-tools.json` with at most 12 `{id,label,url}` entries, at most 16 KiB, distinct bounded IDs, plain bounded labels and HTTP loopback URLs with explicit ports and no credentials/query/fragment. Missing configuration means no tool entries. Invalid configuration is reported without blocking the dashboard.
3. The panel exposes navigation metadata through a read-only same-origin endpoint. Tool navigation uses ordinary same-tab links; no iframe, CORS privilege, reverse proxy or relaxation of a tool's frame policy. Opening a link does not start a tool server, camera or model.
4. Carry the originating panel origin as a validated navigation-only URL parameter so a worktree panel on a different port remains the return target. Tool pages reuse a framework-neutral browser navigation helper. A missing/invalid origin falls back to the tool's trusted local configuration, never an arbitrary remote destination.
5. Plugins Manager is a standalone tool route at `/plugins/`, not persisted Control Panel page state. Legacy `?page=plugins` links redirect to the stable route. Its API remains same-origin and its UI uses the shared shell.
6. Tool maintenance links navigate to a panel confirmation. Query parameters never directly invoke a state-changing request. Remove consumed navigation parameters so reload cannot repeat a request.
7. Keep existing update/restart handlers and freshness indicators. Navigation labels are Control Panel, Plugins Manager, Restart and Rebuild; active-page state, outside click, Escape and arrow-key navigation remain shared.
8. A shared XR Build design-system stylesheet owns tokens, IBM Plex typography, application chrome, controls, cards, tabs, menus and states. The control panel and workspace tool both consume those components; each product keeps only its own layout rules. A render-blocking CSS entry imports the design system and local layout. Minimal inline light/dark background and a pending-layout guard prevent unstyled white flashes while modules load. Reveal after saved source state and fonts settle, without waiting for hardware availability. Startup errors remain readable instead of leaving a hidden page. Shared page identity sets `XR Build · Product Name` titles and designated emoji favicons for tools; selected project icons never replace tool identity. Native app windows receive the manifest name immediately and then follow the app page title.

## Verification

Configuration bounds/URL rejection/missing file; menu order, active state, keyboard behavior and no GET-triggered maintenance; existing panel regression tests and name guard. Tool strict live check/build and delayed-module cold/reload browser tests in light/dark themes, including startup failure and no acquisition/model initialization. Existing tracking tests remain unchanged except startup-structure assertions.
