## Context

Restart already posts to the existing panel endpoint, shows shared in-place progress, closes the old server and relaunches the same Node entry point. Windows launch helpers request hidden execution, but a visible terminal can still appear in the real restart path. Maintenance availability currently uses the warning palette for Restart and for an available Rebuild; only a missing host escalates Rebuild to the error palette.

The auto-routing launcher previously fell back to the checkout workspace when the selected user `.xrbuild` directory was absent. That bypasses the intended first-run Create your workspace setup and exposes repository development projects from the ordinary Start shortcut.

With zero projects, the dashboard currently renders an Unsorted drop target, two New project actions, a large explanatory card and inactive Activity cards. The Plugins Manager similarly keeps an empty Details column. These states compete with the one useful next action and do not match the shared compact empty-state treatment.

## Decisions

1. Reproduce and identify the executable that owns the visible terminal before changing the relaunch path; do not hide the symptom with timing or UI changes.
2. Keep the replacement server detached from the old process and preserve its exact workspace, projects, port and other bounded arguments while removing `--open`.
3. Use only a Windows invocation that creates no console window. Panel-owned launch/restart helpers must not route through `cmd.exe`, PowerShell, a package-manager shell or a visible terminal host.
4. Preserve file-based panel logging so silent startup and restart failures remain diagnosable without a console.
5. Keep Restart on the warning palette and give every active Rebuild state a separate reddish palette across the header chip, menu label, bulb and hover/focus treatment.
6. Keep inactive maintenance menu items neutral and retain the existing text distinction between `rebuild available` and `rebuild required`.
7. Put maintenance colors and indicators in the shared design system rather than product-specific page CSS.
8. Keep the auto launcher in user mode at `XRB_HOME` or `%USERPROFILE%\.xrbuild` regardless of whether that directory exists or is initialized; missing and empty directories use the existing Create your workspace setup.
9. Preserve whether a server was started through auto routing and re-evaluate only top-level panel document requests, so an older auto-routed repository panel can redirect to user mode without affecting APIs, assets, polling or managed capture traffic. Explicit repository launchers remain fixed.
10. Reuse the existing workspace-identity and occupied-port checks. A conflicting process or mismatched panel must fail visibly and must never be reused as the newly selected workspace.
11. Report enough launch/workspace identity from the server for the browser to distinguish an ordinary user workspace from explicit repository development; do not infer it from a hard-coded port or folder string.
12. When an existing ordinary user workspace enters the zero-project state, show a plain `Projects` heading plus a shared `No project yet.` placeholder and `+ New project` action in a standard design-system stack in the project sidebar, hide the Project and Activity regions entirely, and open the existing New project dialog once for that empty-state transition with a `Project name` input focused. Add one short sentence explaining that the dialog creates an app project in the workspace, and keep `Letters, digits, spaces, and dashes.` guidance below the input, preserve the entered display name including casing and spaces, and derive the lowercase folder internally by replacing whitespace runs with dashes. Treat folder collisions case-insensitively and return expected naming conflicts to the same dialog, keeping the field's standard styling while showing only the field-level error copy in red instead of opening the generic failure dialog.
13. Keep Cancel and Escape available even while the project inventory is empty. The plain `Projects` heading, `No project yet.` placeholder and `+ New project` sidebar action remain visible behind the modal and after dismissal so the dialog can be reopened.
14. When the plugin inventory is empty, render only `No plugins installed yet.` in the left list and hide the complete Details region, including its heading and `Select a plugin.` placeholder. Non-empty plugin rendering remains unchanged.
15. Reuse the shared design-system dialog surface for every modal, suppress browser focus outlines on the modal card itself, and keep focus treatment on its interactive controls; do not add page-specific empty cards, messages or controls.
16. Present host rebuild status and streamed output through the shared progress-dialog surface over the active Control Panel, rather than reusing the opaque first-workspace setup treatment or repeating an `XR Build` heading.
17. Treat `design-system.css` and `design-system.js` as the owner of every repeated developer-tool visual and interaction. Migrate repeated control groups, button rows, field grids, supporting text, readouts, segmented controls, switches, compact toggles, sliders, disclosure headings, dialog structure, icon buttons, spinners, filter chips, swatches, tool buttons, floating-menu positioning and resumed component animation to named `xrb-*` components or modifiers. Product styles may position those components in feature layout, but may not redraw their surface, typography, state, icon or interaction. Shared icons replace product-owned inline SVG markup.
18. Treat an ordinary panel-created user workspace as a mutable generated package graph: use non-frozen pnpm setup whenever its install is absent or stale, and write a fingerprint of the root workspace files and package manifests after success. Adding a project or changing dependencies then invalidates readiness even if the old lock still matches the virtual-store lock. Also verify package-local dependency links for dependency-bearing workspace packages, because deleting and recreating an identical project can preserve the same fingerprint while removing the links needed by its dev script. Explicit and repository-development project roots retain frozen installs and the committed-current-lockfile requirement.
19. Keep raw generic error output in a fixed-height, scrollable monospaced shared copy area so even short errors read as diagnostics rather than a one-line field. Show the stable description `XR Build could not complete this action. Review or copy the details below.` instead of repeating error text as prose, provide one standard transparent shared icon button that writes the complete error to the clipboard, and reuse the same copy-block component for job logs. Reserve a one-line live status below the block so `Copied to clipboard.` can appear and clear without moving or resizing the dialog. Dismiss generic errors with the existing shared corner Close control and omit the bottom action row.
20. Use the shared primary accent color for the product menu's current-page checkmark so selection matches primary buttons and active navigation rather than reading as success status.
21. Repair a stale project selection against the loaded inventory before rendering details. Prefer the remembered view when it contains a project, otherwise switch to the first available live or archived project, persist both values and force the newly resolved detail to render. Remove the retired `No projects yet` instructional card entirely so stale detail DOM cannot contradict the visible project list.
22. Make Projects and Archive tabs cross-inventory drop targets. Project rows remain draggable in either normal inventory view; dropping on the opposite tab calls the existing archive or unarchive endpoint, opens the destination view and preserves selection on the moved project. Use one shared `xrb-drop-target` tab state, and refuse the Archive target for running projects just as the context menu omits that action.
23. Do not reserve a stable root scrollbar gutter. Let the shared application header use normal block width so it reaches the viewport edge when no vertical scrolling is needed, while content taller than the viewport retains the browser's normal vertical scrolling and never gains horizontal overflow.
24. Keep two to five PR Implementation outcomes as authoring guidance, but make trusted promotion enforce only a minimum of two valid outcome checkboxes. Larger changes may retain additional independently meaningful outcomes instead of combining them solely to satisfy an arbitrary maximum.

## Risks and mitigations

- A hidden relaunch can fail without visible feedback. Preserve the existing log destination and add bounded tests for the exact executable, arguments and window options.
- Over-broad process changes could alter startup identity or workspace selection. Keep argument preservation under focused unit coverage.
- Red can imply a fatal error. Restrict the reddish treatment to the active Rebuild action and retain explicit status text; Restart remains amber and inactive Rebuild remains neutral.
- Refresh-time routing can loop between panels. Carry explicit auto-route identity, compare canonical selected roots and redirect only when the current server no longer matches the current directory rule.
- The newly selected default port can be occupied by another workspace. Reuse the existing refusal behavior and show a bounded page instead of redirecting to unrelated content.
- Live project updates can repeatedly reopen or replace the creation dialog. Track an empty-state transition separately from routine renders and never replace a dialog while the user is typing.
- Hiding columns can leave stale focus or docked actions. Clear selection, hide run/detail docks and move focus into the required creation input.
- A broad component migration can cause subtle visual drift. Keep product-specific geometry as layout hooks, provide explicit compact/fill/accent variants for real differences, and enforce ownership through static regression tests plus browser smoke coverage.
- Non-frozen installs can weaken reproducibility. Permit one only when an ordinary panel-created user workspace has no lock; use frozen installs after creation and for every explicit repository.
- Error logs can dominate or resize dialogs. Bound the shared copy block and keep the complete raw text available through scrolling and clipboard copy.
