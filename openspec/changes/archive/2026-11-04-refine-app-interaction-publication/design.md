## Decisions

1. Keep one SDK Escape owner. A validated launcher return uses the same navigation/sound path as X. Without a return target, do nothing regardless of fullscreen. Delete automatic native fallback and pre-browser quit routing, while retaining explicit close APIs and panel Stop/window-close controls. Ordinary browser security/fullscreen behavior remains browser-owned; do not promise scripts can override it.
2. Keep Segmented default visuals compatible. Add an opt-in non-latching cap style; the showcase opts in and stops requesting reselectIndex. User input moves the cap while pressed and release restores its resting height; selection color stays. Programmatic selection and disabled-state handling retain existing semantics.
3. Share one Apps emoji value and the same theme-aware, detail-preserving tint between the sidebar and Apps favicon. Refresh the favicon when the theme changes. Avoid brightness-zero silhouette filtering, which erased every detail into a solid square. Other glyphs keep their existing treatment.
4. Correct the toolbar's trailing action by compensating for internal icon-button padding, not by shrinking the clickable area or moving centered filters. Verify actual glyph bounds at multiple widths.
5. Publication is an app deployment operation, not a package-target capability. Make status, validation, publish and unpublish eligible for app projects across host/web targets and platform choices. Keep non-app projects ineligible. Use selected-destination status for action, slug, URL and optimistic feedback; lock publisher and slug while published/pending and during status checks. Preserve failed-but-deployed records, unavailable-provider errors, confirmation and queued operation identities. A late HTTP start response must not overwrite a newer terminal job event and leave publication stuck in its spinner. Existing explicit route-move API confirmation remains intact. No live publication changes during tests.

## Verification

SDK tests cover direct/return, fullscreen/windowed, repeat and disposal. Native build/tests verify absence of automatic Escape closure. Control tests cover hand/mouse cap press/release and same-axis re-selection. Panel fixture tests cover published host/platform apps, initial checking, failed deployments and publish/unpublish actions without mutating target/platform. Browser tests cover detailed glyph rendering, Activity optical alignment and locked publication fields. Test servers use ephemeral ports, not shortcut port 5181.
