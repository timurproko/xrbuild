# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Opening Hands never starts capture; Start uses the saved native provider without generated tracking or an automatic fallback.
- Managed native apps and Hands share exclusive acquisition, identify occupied owners and never implicitly stop another session.
- Authentication, bounded newest-frame credit, clock mapping, freshness and epoch fencing protect SDK admission and teardown.
- Immediate profile commits acknowledge actual SDK application per target; geometry clears holds while appearance preserves them.
- Raw recording hooks retain original HANDS packets and a frozen portable profile, and validated replay applies that profile once without a recorder UI.
- Start and Stop sit above the provider on the simplified page, with frame-derived fps, compact state and SDK-only pinch and drag feedback.
- Provider metadata preserves existing app-compatible data lookup without calibration migration; new core state stays workspace-owned.
- Native sessions support Windows x64; other platforms and WebXR receive explicit guidance, and no physical hardware accuracy or latency is claimed.
