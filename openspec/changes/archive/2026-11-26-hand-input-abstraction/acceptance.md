# Conditional implementation acceptance

Verdict: accepted only when an authorized human directly merges the containing exact pull-request head after required current-head validation, explicitly asks the active agent to execute that protected exact-head merge while it is currently eligible, or personally enables native auto-merge for the unchanged head and GitHub integrates it after validation succeeds.

The maintainer integration decision accepts these scenarios:
- Apps expose Mouse, Keyboard and Hand; old provider names use the global source and canonicalize on the next settings Save.
- Hands owns one revision-safe source choice, with a unique-real initial default, visible availability and no silent replacement.
- Native provider settings and pinch, grab and palm signals retain the existing ABI and shared SDK processing.
- Native, dev, browser and packaged contexts receive resolved source policy without a hardware bridge or private-source dependency.
- Fresh managed apps attach common SDK hands automatically; Launcher, UI Kit and the template contain no hand-provider wiring.
- Position, size, appearance controls and the live laboratory remain the immediate following work, outside this implementation.
