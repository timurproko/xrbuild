# Design

## Progress and readiness

New linked drafts start with two to five unchecked, outcome-sized `## Implementation` items and the existing machine-readable link. Preserve version-1 links and historical plain-bullet bodies on the old ready/finalization path; only newly authored draft checklist bodies opt into automatic promotion. An agent checks detailed tasks after their verify clauses hold and checks the corresponding body item after code and tests exist. `## Acceptance` contains plain observable outcomes, not progress or an agent's claim of human approval. Device-only checks can be recorded as unresolved gaps for maintainer inspection; they must not be falsely marked as verified tasks.

A trusted `pull_request_target` handler runs the base branch's scripts and pinned validation tooling; it never installs or executes PR code. It accepts only an open, same-repository, linked draft into `main`, with a valid checklist and acceptance list, all task markers done at its exact head, and no conflicting active-change association. Before calling the App's ready mutation, re-read PR number, node identity, body, base and head SHA to refuse races. An incomplete checklist or tasks file remains draft with a readable reason. A completed but invalid candidate fails visibly, never promotes. A bot-driven `ready_for_review` event invokes the current finalizer, whose archive commit triggers full CI; after the bot push, required validation is for the finalized head. Do not let the draft's lightweight green check count as implementation acceptance.

## Session/worktree binding

Extend the existing `tools/worktree` command with an idempotent create/re-enter operation. Resolve the registered worktree and branch before reuse; reject collisions or a dirty worktree claimed by a different task. Print an absolute path for the caller, make dependency installation use the pinned package manager even when only `corepack` is on PATH, and recover or report a partially created worktree rather than silently leaving an unusable checkout. Agent instructions must explicitly direct all edits and scratch to the bound worktree. A Claude Code worktree-create hook can return that path for native session entry. Pi's session cwd is fixed at launch and is also used for resource discovery: supply a launcher that starts Pi with the worktree as its process cwd (or a tested SDK session with an explicit cwd); do not advertise a hook as moving a live Pi session. When re-entering an existing Pi session, refuse mutation until the path is confirmed and use explicit absolute paths if it cannot be relaunched.

## Compatibility and rollout

Keep PRs already ready under the old fence behavior, including in-flight changes. Ensure the new readiness workflow cannot promote a plan-only draft merely because planning tasks were prematurely checked: require implementation outcome checkboxes, acceptance, and exact-head task completion. Do not alter documentation-only auto-merge or grant bots implementation-merge authority. Merge the policy through the current checks before relying on it for subsequent PRs; any changes to an existing PR's verification tasks require an explicit, separately reviewed refinement.
