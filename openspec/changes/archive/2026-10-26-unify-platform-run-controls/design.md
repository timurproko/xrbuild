# Design

## Platform choices

Keep the manifest's `target` (`host` when omitted, or `webxr`) and `platform` (empty for standalone) as independent storage fields for compatibility. The UI uses an ephemeral combined choice, not a new manifest property: `host:` for Desktop, `webxr:` for WebXR, and `<target>:<provider-name>` for a platform. The colon is unambiguous because provider names contain only lower-case letters, digits and dashes. A native platform reported by the host or a native packager has target `host`; a packager declaring `webxr` has target `webxr`. Describe unavailable and disabled selections without offering disabled plugins as new choices. Render the choices as a connected segmented control of compact secondary buttons, sharing borders and rounded only at the outer ends; the current choice stays highlighted and exposed through `aria-pressed`. Keep one continuous row with horizontal scrolling when it exceeds the available width; the segment labels stand alone without tooltips. Contain the active segment's stacking order so it never paints over the sticky column header while the page scrolls. Selecting a segment updates a hidden form value to reuse the existing manifest autosave. An unavailable stored selection remains readable but cannot be chosen anew.

Changing the combined choice saves only `target` and `platform` in one manifest update, under the existing mtime check. The host standalone choice may leave `target` unset. Preserve Display, Input, saved plugin settings and inactive target selections when changing unrelated settings. Do not change platform metadata or the packager ABI.

## Project cards

Move Platform to Settings; remove Runs on and the duplicate Build Platform control. Align the Platform button group, Display and Input vertically in the left Settings column. Put only the display's contextual Fullscreen or 2D checkbox in the right column centered vertically on the Display dropdown, without an extra heading; on narrow screens place it after Display. Move the native Dev server checkbox from the project header to the right side of the Settings header, beside Open JSON, without changing its checkbox-and-chip styling or per-project remembered mode. Display and Input stay visible only when the effective choice is native. Build always starts with the web Build action directly under its heading, at the same heading-to-control spacing as Settings to Platform. When a valid packager is selected, Package title, Package version and Build package share one row directly below web Build at desktop widths; on narrow screens this row stacks rather than overflowing. Other identity fields, including Package ID, remain editable below that row. The version input stays a draft until Build package is clicked; it is not autosaved to the manifest merely by typing. When there are no package fields, do not render an empty settings gap or a divider above the lone web Build action. When a selected packager is disabled, show the standalone choice for its stored target without modifying the manifest.

Use one primary **Run** control. For the native target it follows the existing built/dev-server host run flow and turns into Stop when a host runs. For the WebXR target it opens the built project's `/preview/<id>/` page in a browser tab and is disabled with a Build-first hint when the entry is absent. The opened browser page may itself offer immersive entry on compatible hardware; Run must not call the host run API, claim a remote headset launched, or display native host FPS for it. A short local UI note may say the browser preview was opened without claiming to track its lifetime.

## Verification and preview

Cover the combined choices, target/platform atomic save, disabled and mismatched packagers, legacy manifests, and Run dispatch with panel tests and a browser check. After the implementation is approved, run the task worktree's panel at `127.0.0.1:5180` with the existing workspace while the primary panel is stopped. The primary checkout remains on `main`; restoring it consists of quitting the preview panel, restarting the primary launcher and restoring its editor config. The preview must not trigger a package or native rebuild simply to show UI changes.
