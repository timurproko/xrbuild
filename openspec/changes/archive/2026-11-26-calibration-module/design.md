# Design

## Context

See proposal.md for motivation. PR 51 head `a99213573204ce104c2a99316eebb9619f91ed61` retains `CameraCalibration` in `embedded/plugins/input-hands/samples/hand-tracking/src/live/multiview/viewer.ts`, manual fitting/validation, automatic marker collection, native protocol/geometry and preferences storage. Its retained HTML fragment is not served. The coordinator accepts injected camera/storage ports but does not own transport or a shared acquisition lease. Core `HandsTools` demonstrates owner-qualified checked exports; its browser allowlist deliberately excludes capture/calibration. The legacy `RgbdSession` still imports the hand estimator, so mounting that whole session would violate the minimal dependency boundary.

## Goals / Non-Goals

**Goals:** Deliver a complete separate camera-measurement module, preserve all existing scalar compatibility and make resource ownership and consumer validity explicit. Software acceptance uses injected ports and disposable workspaces only.

**Non-Goals:** No provider implementation, hand inference, landmark/fusion view, generic depth laboratory, recording feature, app/global profile adjustment, automatic runtime setup or personal-workspace operation.

## Decisions

1. **Core shell, optional checked contribution.** Add a permanent Calibration item to shared navigation and reserve `/calibration/` as a core route. Reuse the existing app bar, theme, cards, fields, buttons, status and dialogs. Resolve the optional contribution through the existing owner-qualified plugin export/runtime checks, with a calibration-only browser asset allowlist. Keep concrete camera integration in the approved embedded plugin, not a core device branch. Do not widen the recordings allowlist into an acquisition boot or restore an old tool route. Missing plugin/build is a one-line shell state; native/device failures affect capture, not offline scalar operations.
2. **Small UI on retained coordinator.** Layout: camera A/B serial/profile selectors with explicit Connect/Refresh as needed and Start/Stop; two RGB previews for marker feedback/manual probe clicks; Manual/Marker method choice; compact progress, residual/quality result and Saved/Save/Import/Export controls. Manual includes target ID, fit/check role, paired-target list, remove/clear, fixed-rig confirmation, reference description/uncertainty and Fit. Use a concise results summary rather than a laboratory dashboard. Purpose line: “Camera B → A transform, bound to camera serials and profiles; hand providers can use it.” Draft replacement requires an explicit clear/confirmation; evidence/selection changes invalidate affected pending fits/results.
3. **Minimal native transport and shared ownership.** Extract the authenticated connection, inventory, packet/run/sequence/clock checks, RGB preview decode and calibrated point sampling needed for calibration from mixed session code; exclude estimator, hand reconstruction engines and fusion imports. Reuse checked source-bound bridge services with coupled two-camera rollback. Acquire the panel's shared acquisition exclusion before either camera starts, integrating the live-session seam if delivered by implementation time; otherwise add the neutral lease seam that both entry points must use. Reject active app/provider conflicts rather than stopping them. Keep credentials in memory, enforce loopback/origin checks, bound work/backpressure and release only owned resources on Stop, disconnect, page disposal or failure. Navigation performs metadata reads only; connecting/enumerating and native startup are explicit actions, never builds/downloads.
4. **Retain algorithms, expose their real status.** Manual uses existing static-target sampling and proper rigid fit with six fit/three held-out pairs and 15 mm RMS, 30 mm max, 8 px reprojection gates. Marker uses existing native corner/depth observations, twelve paired groups over at least 1.8 s, eight fit/four held-out groups and repeatability checks. Show collection/rejection state and provisional versus spatially qualified results. Marker-disabled/manual capture must not depend on marker detector availability where manual prerequisites suffice. Fix any coordinator adapter gaps with focused tests rather than resurrecting the old fusion viewer. No identity fallback, inference workers or automatic provider application.
5. **Unchanged scalar storage and documented output.** Reuse revision/lock/same-origin/regular-file protections in `recording-store.mjs` via a storage adapter; write only `handtracking.fusion-calibrations.v1` in selected workspace `config/plugins/input-hands/preferences.json`, preserving unrelated values. Retain version-1 inventory and eight-record bounds, bounded scalar imports/recomputation and existing setup-wrapper compatibility. Explicit Save persists qualified manual or marker results; Export can retain provisional evidence. Import/list/export need no bridge or camera. Malformed, linked, busy or conflicting state remains intact with an error, never reset. Documentation under `docs/` links the precise existing plugin format, identity binding and validation rules instead of inventing a second schema.

## Output contract

Keep `xrbuild-spatial-calibration` v1 and existing export filename. `pA = rotationRowMajor * pB + translationMeters` maps B RGB optical to A RGB optical metres (+X right, +Y down, +Z forward). Document required source serials, color/depth/aligned profiles, intrinsics/extrinsics, depth scale, source/evidence hashes, residuals and qualification fields against the actual validator and representative fake-data round trips. Consumers must validate/recompute integrity, match current identities/profiles and reject a moved rig; hashes cannot detect physical camera movement. Preserve `physicalValidation: operator-required`, `temporalAlignment: null`, `fusionEnabled: false`. Spatial qualification is neither a synchronization certificate nor physical accuracy acceptance and does not affect `config/hands/profile.json`.

## Risks / Trade-offs

- [No physical cameras or native runtime available] → Fake-port lifecycle, marker/manual packets, storage and browser checks establish software behavior only; operator checklist remains mandatory.
- [Mixed session import silently loads inference] → Assert the shipped calibration import closure excludes hand-estimator/fusion boot; test Start with no model assets/workers.
- [Concurrent live-session development] → Keep one neutral acquisition exclusion, recheck the delivered seam before wiring starts and test busy/partial-start/disconnect behavior rather than introducing independent conflicting owners.
- [Legacy results mistaken for current physical acceptance] → Show source/profile identity and qualification; import never confirms the present rig or timing.
- [Stacked PR diff includes PR 51] → Base on its head now, explicitly identify that dependency, then rebase onto main after its merge before final implementation publication. Do not implement or merge PR 51 here.

## Migration Plan

No user-data migration or cleanup. Ship new navigation/page and checked calibration contribution with the unchanged readers/storage. Rollback removes only new product wiring; existing results and exports remain usable. Update the pending-module wording in Hands/calibration docs and the Hands boundary spec.

## Targeted acceptance and operator handoff

After approval, run only changed-area coordinator/manual/marker/protocol/storage tests and isolated navigation/page/browser checks. Use fakes for failed/partial starts, Stop races, stale packets, profile changes, marker rejection, qualified/provisional results, import/export recomputation, unchanged legacy inventories and revision conflicts. Browser checks cover passive load, concise unavailable states, controls and default-window layout using only task-owned disposable state. All scratch/proof stays in the crew task folder, and all owned processes stop before reporting. Publish the final head, trigger CI and report without waiting or polling.

Operator checklist for implementation handoff: (1) explicitly connect the checked bridge and select two serials/profiles; (2) hold cameras fixed and collect at least six manual fit plus three held-out targets, inspect residuals and Save/Export; (3) collect the marker workflow and inspect its qualification/rejection feedback; (4) reload and import/export the result, check identities and preserved preferences; (5) Stop/disconnect and retry with changed profile or busy camera, confirming honest refusal and resource release. Actual capture, marker detection, depth geometry, physical accuracy, timing and hardware release remain unverified until performed on the person's two-camera rig.
