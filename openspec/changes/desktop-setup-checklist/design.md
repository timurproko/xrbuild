## Installation authority

Only fixed server-owned action IDs are accepted, with explicit consent and the current checked revision. Build tools use the exact allowlisted package ID from the standard trusted package-manager source and its normal integrity checks when available. Without that manager, a Windows system PowerShell capability enables a fixed official HTTPS build-tools bootstrapper fallback: download only after Install, bound size/timeout/redirect destinations, create exclusive fresh installer storage, validate its SHA-256 continuity and valid provider Authenticode signature while holding a write/delete-denying file handle, then launch only that checked executable with fixed component/no-reboot/wait flags through normal system elevation. Never install a package manager or disable signature/hash checks. Preserve failed installer generations for review. Status checks detect capability only and never download or start verification/install processes. No shell commands, paths, URLs, package IDs or installer arguments come from HTTP input. Do not bypass package hashes, elevation or provider license requirements. Clicking Install or Repair is the explicit consent action; no separate checkbox, legal/disclosure paragraph or extra confirmation is required in the checklist. Retain installation scope/license/elevation guidance in the setup documentation and honor provider requirements and system prompts. Only that click sends the server's required confirmation flag; opening/refreshing the checklist never consents or installs. No automatic reboot flags are allowed. Installer restart codes are recorded and shown until a subsequent boot; failed/restarting setup is never labelled ready from exit code alone.
