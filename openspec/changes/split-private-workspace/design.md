# Design

## Boundary and scope

The public core and private workspace become independent repositories. `.xrbuild/` remains the explicit development path, ignored as a whole by the core, with its own `.git`. It is neither a submodule nor a link into another task's workspace. Ordinary `XRB_HOME`/home-directory resolution and separate project repositories remain unchanged. Core code continues to access integrations through neutral contracts.

This PR prepares the core, regression tests and migration documentation. Production history extraction and hosting changes require separate confirmations. The primary checkout stays on `main`; agents do not commit its existing launcher edit or change its tracked workspace in place. The maintainer must preserve that edit before the workspace extraction snapshot is selected. Stages 1 and 2 have now preserved the snapshot and populated the private repository; the maintainer chose not to import the local launcher setting. Core detachment was implemented in this PR branch. The maintainer subsequently chose to leave the old PR unmerged, keep the original repository as a private archive, and bootstrap a new public core with one initial commit. This explicit one-time bootstrap is not a recurring bypass of normal core PR delivery.

## Core changes

- Replace workspace-specific ignore exceptions with `.xrbuild/`; remove obsolete workspace LFS/export attributes and workspace-push hooks/tool/package references. Keep repository launchers and scripts selecting `.xrbuild/`.
- Remove private asset/runtime jobs and change filters from core CI and its required-job dependencies. Private CI belongs to the private repository, checking out a selected core revision and using `XRB_CORE`; generic verification must accept an explicit workspace path rather than assuming the core owns one. Move existing private integration assertions out of the core design-system tests into private tests without losing assertions. Retire all LFS-only core hooks; the independent workspace installs its own LFS hooks.
- Cleanup refuses any task-local `.xrbuild/` path (including links or an unversioned workspace) and an `.artifacts/KEEP` marker, so an outer clean index cannot authorize loss of private files or migration backups. Protected worktrees are reported as dirty/preserved by sweep. Worktree dependency sharing covers core `third_party/` only. Never junction the whole workspace or implicitly edit the primary clone. Authorized developers explicitly provision task-local workspace clones; instructions must cover their independent branch/commit ownership and preservation before core worktree cleanup. Public clones require no private credentials.
- Fix governance's expected repository name to match `xrbuild`, retaining the explicit apply confirmation and adding rejection/acceptance tests. No governance apply is performed during implementation.
- Update current instructions and documentation, including `AGENTS.md` if needed and OpenSpec context. Historical archived specs remain historical; new deltas replace the active versioning contract.
- Defer license text, commercial terms and dependency notices to a separate task as requested; no license grant is added. The original archive and workspace stay private. The maintainer has explicitly created the empty public destination; its first upload still requires a clean audit and an approved exact ref. Disable Actions until the separate workflow/bootstrap setup is ready.

## Ordered migration gates (separate from PR completion)

1. **Snapshot and recovery:** inventory all branches, tags, stashes, worktrees and local changes again. Preserve the launcher edit and any later work with owner approval. Keep a recoverable Git backup plus all referenced LFS objects; a Git bundle alone does not contain LFS binaries. Record exact source revisions and independently verify backup readability.
2. **Private extraction:** split the entire `.xrbuild/` subtree, including historical deletions, at the approved snapshot in isolated staging. Re-root the source `.gitattributes` LFS patterns into the extracted repository. Check source/extracted tree equivalence before the extra setup commit, all historical LFS object availability, and plugin tests. Add private instructions/CI only under the private repository's rules. Explicitly upload LFS objects before a maintainer-approved branch push; agents never push `main`. Verify a clean independent clone with materialized binaries before detaching the working workspace.
3. **Core detachment:** the implementation branch is the reviewed source snapshot, not an ancestor of the new public repository. The selected fresh-bootstrap route does not require merging the old archive PR. Agents do not merge or update primary main. For a maintainer who instead chooses the original PR route: Before updating the stable checkout, back up its entire working workspace, including ignored/local-only files. The old index tracks the workspace, so a checkout/pull crossing the removal commit can delete files. Restore/provision the independent nested clone only after the core index no longer tracks it. Avoid the handoff's unchecked metadata-only conversion shortcut unless its new attributes, index and LFS status are verified. Clean core and private status are mandatory.
4. **Fresh core export (selected):** export only tracked core files from the reviewed detachment revision into empty task-local staging, then overlay only explicitly reviewed tracked migration-documentation updates. Do not copy ignored files, `.xrbuild/`, `.git`, old refs, LFS objects or any backup artifacts. Initialize a new Git repository on a bootstrap branch and create one parentless commit. Verify the complete tree against the selected source and overlay allowlist, retained workflow hashes, a one-commit reachable history and no object alternates. The existing history-filter fixture remains useful but no production history rewrite is needed.
5. **Independent audit:** inspect every reachable commit tree for the forbidden path, all reachable blob contents for private LFS pointers and prohibited identifiers, and commit/tag messages for publication risks. Scan all approved refs, not just the tip or a diff (merge commits can hide tree content from a plain log patch scan). Keep detailed private findings in ignored task artifacts. Verify in a second fresh clone containing only intended refs. Generic documentation mentioning `.xrbuild/` is permitted; private file history is not.
6. **Hosting and cutover:** the maintainer renamed the original hosting repository to a private archive and created a new empty public destination. Disable Actions while preparing/importing the fresh snapshot. The maintainer initializes remote main using only the audited fresh bootstrap ref; agents never push main. Independently clone and audit the uploaded result before replacing any local checkout. Preserve the original local checkout/backups and install a fresh core clone with an independent nested private workspace. Later configure the bot App, credentials, governance, rulesets and test-PR delivery before enabling normal CI. Pending OpenSpec synchronization goes through that restored delivery workflow, not a fabricated bot commit. Never merge old unfiltered branches into the public repository.

## Audit tool behavior

Accept a repository path and explicit publication refs. Resolve immutable commit IDs, enumerate their full reachable history and inspect trees/blobs; missing objects, unsupported inputs or an incomplete scan fail closed. Report bounded, neutral summaries with failing object IDs, not private source contents. Reject any historical `.xrbuild` tree entry or gitlink, private workspace LFS pointers and known prohibited names outside the permitted naming boundary. The tool must not mutate refs, prune objects, upload data, rename repositories or change visibility. Fixture tests include a deleted private file, a merge-only private tree, a private tag/ref, a pointer moved outside the subtree, a clean export and invalid/missing refs. Manual review remains necessary for unknown proprietary material, credentials and licensing; a name guard alone is not proof of public safety.

## Risks and open decisions

- **License follow-up:** out of scope for this split, at the maintainer's request. Record the intended free personal/nonprofit use and paid commercial production policy only as a future decision input, not as an effective license grant. The source-visible bootstrap does not grant the contemplated commercial/personal-use permissions; licensing, copyright authority and dependency notices require separate review.
- **Private CI bootstrap:** until the core is public, the private workflow needs approved read access to the private core or must wait for publication; no private token is added to public CI.
- **LFS history:** present files are insufficient evidence; every object referenced by retained workspace history must be available privately.
- **Local-only material:** ignored build products may be disposable, but ignored credentials/settings must not be deleted or copied into public artifacts.
- **Independent task workspaces:** cleanup must not discard a private clone's uncommitted or unpushed work merely because the surrounding core worktree is clean; add a guard/test or refuse automated cleanup while nested Git metadata exists.
- **History identity:** the new core begins with a single parentless commit. Old core refs, PRs and stash history remain exclusively in the private archive; none become ancestors of the new initial commit.
- **Fresh hosting is essential:** force-pushing the old repository does not reliably remove PR-reachable commits, LFS storage or cached artifacts.
