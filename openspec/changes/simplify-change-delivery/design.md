### Planning versus implementation

Analysis, remote administration and real planning-only publication need explicit repo/base/head, not a checkout or runtime. Support ordinary CLI/API and stdin; an optional helper publishes only the selected change folder, with create-only refs, expected-head writes, duplicate discovery and recoverable partial publication. In-memory/session scratch is allowed for no-checkout operations; implementation scratch stays in its own artifacts.

Keep repository/branch/history/change/PR across machines; adopt a verified remote proposal or unoccupied local branch without resets. Preserve dirty owned resumes; report divergence, existing ownership, path collisions and unavailable dependencies separately. Dependency installation is explicit/need-based. Existing CLI aliases remain compatible. A1 enter/attach success is authoritative without a second inventory ritual; external agents use ordinary Git without A1 installation.

The optional repository helper verifies the selected repository, primary branch, Git worktree registration, task ref and observed head before adopting history. New unoccupied local/remote branches require a fresh fetch and scoped acquisition lock; remote-behind local commits are retained, while divergence blocks. It never moves an existing checked-out branch to a remote tip: a changed remote tip is reported for explicit Git integration. `add`/`enter` perform no implicit dependency setup; `--install` explicitly requests it. Optional `--a1` invokes the supported attach command and treats only its successful exit as ownership confirmation. Matching existing checkouts (including dirty ones) require a successful ownership adapter before helper resume; a missing/unverifiable adapter blocks that helper route without requiring external agents to install A1. External agents retain ordinary Git worktree operations and their own ownership establishment; the helper does not invent a runtime identity or infer ownership from a clean status. Git locks, foreign registrations, mismatched refs and unsafe path components block before setup, and context/head are rechecked before any requested dependency action.

Portable handoff performs fresh read-only remote-ref inspection and local ancestry verification, fetching only the observed remote object when necessary. It reports local/remote heads, Git dirty state and commit publication separately; unavailable identity/remote evidence is an explicit unverified result, not a claim that a clean or detached checkout is published. The existing handoff file remains a local record with no cleanup enrollment or acceptance effect.

### Handoff and safe local-only removal

Report repository, branch, change/PR, observed local/remote heads, publication status, remaining work and optional path. Clean status/detach/release does not prove push. No local handoff registration is required for remote-only drafts.

An explicit local-only removal request targets one checkout. Fresh read-only remote evidence must contain local HEAD; equal tips are not required when another machine safely advanced the branch. Open PR, pending CI, unfinished scope and absent archive/acceptance are irrelevant to this route. Keep remote refs/PR and local branch by default. Never reinterpret this as abandon/discard permission.

Replace force/recursive fallback with bounded lstat-based inspection, scoped locks, identity/claim rechecks and non-force Git removal. Unknown ignored files, private .xrbuild data, nested repositories/submodules, KEEP, dirty state, unsafe paths, live/unverifiable owners and unpushed/divergent commits remain protected. Disposable caches are narrowly enumerated; user data cannot be inferred disposable from .gitignore. Private preservation is a separately authorized operation, not automatic export. Preserve useful partial state and report blockers rather than retrying destructively.

The standalone published-removal engine admits one registered linked checkout and retains all branch refs. Its default ownership provider is unavailable until a trusted claimant adapter is supplied; clean Git state is not substituted for ownership proof. The programmatic verifier must return an available, target-bound, generation-bound observation and is re-read during execution. CLI paths without such support report an incomplete ownership/runtime prerequisite, not a successful removal. Ordinary standalone Git operations remain available independently; no A1 identity or ownership-assertion CLI flag is invented.

Content inspection is bounded, link/hardlink-aware and hashes actual regular source bytes against the index (with checked text line-ending normalization), not just cached stat-based status. Actual nested metadata, gitlinks, configured submodules and nonstandard worktree Git metadata block disposal; a clean tracked regular `.gitmodules` alone does not. No ignored/cache payloads are admitted for automatic disposal in this checkpoint: generated dependencies/output and handoff scratch remain preserved until separately reviewed. The normal Git-generated linked-worktree marker and fixed administrative-file inventory are the only non-source content admitted. A per-target create-only journal in common Git metadata binds physical checkout/admin identities, branch/head and content fingerprint. Rechecks and non-force `git worktree remove` are scoped to that identity. Failures leave a recoverable journal; retries cannot erase recreated paths or replaced metadata and never use recursive/force fallback. Legacy `--discard` reports its separately unsupported authority rather than silently deleting unpublished refs or remote work. Explicit sweeps recheck merged eligibility and use the same preservation/publication engine; they gain no open-PR authority.

Merged completion and explicit local removal use exact-target entrypoints; sweeps stay explicit separate bulk operations. Replace .a1/worktree.json broad completion with an exact operation after the compatible A1 API is released. Preflight before detach; trusted repository deletion only after shell exit and fresh rechecks. No runtime deletion fallback. Existing ordinary Git/standalone cleanup remains available; missing runtime support is a clear blocker, not permission to sweep. Repeated operations preserve recreated identities and unrelated worktrees.
