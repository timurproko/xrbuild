# Design

## Context

See proposal.md for motivation. Inspected baseline is main `48a59a5`, including PR 48. PR 51's planning design at `7fa33aa` explicitly reserves an empty-frame-capable SDK adapter and this exact headless/exclusive follow-up. PR 50's inspected design and implementation head `b185c44` own profile validation, geometry/appearance, ordered Apply and mountable controls; neither dependency is merged or assumed implemented on main.

Observed seams and constraints:

- `native/host/src/plugins.{h,cpp}` provides neutral discovery/loading; `providers.{h,cpp}` creates input handles and bridges borrowed callbacks. `XrbInputApi.stop` guarantees no callbacks after return. There is no live provider-settings operation.
- The ABI uses panel-space metres, host QPC milliseconds and unchanged 456-byte `XrbHand` data. Its function tables and borrowed frame pointers require validation and immediate bounded copying, not retention.
- `main.cpp` starts input inside the full host, which also owns a per-logon-session full-host singleton. Removing that singleton or starting another complete display/CEF process would not arbitrate cameras safely.
- `providers.cpp`, built-in inputs and the current channel are entangled through clock/serialization/registry symbols. The host CMake configure currently requires CEF before defining any targets. A new executable merely added to that graph would not be independently headless-buildable.
- Panel `runNative`, `effectiveSelection`, `runtimeConfig`, host freshness and `HostRunner` own managed built/dev acquisition. Browser previews do not load native input. `server.ts` has no server WebSocket dependency; its existing permissive preview CORS must not be reused for session controls.
- `HandFrameIngress` is the common SDK admission seam; PR 51 promises its scene adapter with reset/dispose, and PR 50 supplies the one-time profile transform and release semantics. The old diagnostic's raw filter-disabled path is not suitable.

## Goals / Non-Goals

**Goals:** one supported native camera owner, a supervised small worker, bounded/fenced trusted transport, and an actual session feeding the existing page with app-equivalent processing. No profile, plugin or user-project migration.

**Non-Goals:** simultaneous observation of an app, camera/debug images, new gesture math, runtime/model setup, WebXR acquisition from the worker, automatic restart, legacy recording migration, post-processing, mesh, proprietary plugin edits, or a universal machine-wide camera broker. A native provider can be installed but still fail on real hardware; fake tests cannot settle that.

## Decisions

### 1. Sequence with the page and adjustments

Keep this plan-only PR into the actual default branch, main. Do not copy PR 51's page or implement a parallel viewer. After approval, use this same task branch and incorporate PR 51 **including its PR 50 integration** before implementation. Prefer merging their delivered code from main; if parallel timing demands it, integrate the approved page head locally and retain main as the PR target. Do not merge, mark ready or edit either dependency PR. This PR stays blocked/draft until both dependencies land.

The `Minimal provider picker with availability` delta intentionally carries PR 51's complete replacement requirement and preserves its scenarios, except the obsolete page-only limitation becomes explicit live delivery. Before finalization re-read the merged specs and reconcile additional scenarios from 50/51, rather than reverting their requirements with a stale replacement. PR 51's latest approved simplified page supersedes the earlier shell: it retains Calibration and Record tool tabs, removes legacy routes without redirects and removes obsolete laboratory code. This PR consumes those actual mounts and does not restore Output/Stats tabs or removed workflows.

Estimate: **5–8 engineer-days** after the seams are available, excluding device acceptance. This plan includes small SDK pinch/drag targets, not a general test laboratory. If their implementation proves larger than the existing SDK target primitives allow, do not silently omit the approved outcome: seek a scoped plan amendment and list real-hand targets as the next step.

### 2. One conservative native acquisition lease

Add a shared Windows lease helper used by the headless worker and all newly built native hosts **before input create/start**. Use one conservative native-hand acquisition slot per Windows user/logon session, not a per-workspace/plugin key: different aliases/providers can use the same cameras. Built-in synthetic/replay sources use the same lifecycle, although they do not need cameras. A native app with Hand off does not reserve it; browser XR is a distinct context.

The acquisition process owns a secured named kernel mutex on a stable user/session-qualified name independent of repo path, checkout, panel port or source owner. A dedicated lifetime thread owns/acquires/releases it, respecting mutex thread ownership. A paired bounded, user-ACL-protected mapping stores advisory owner kind, app display name/project ID, panel instance, PID plus process creation identity, session/source and protocol version. Publish metadata while holding ownership, validate/sanitize it on reads, and report generic busy if unreadable. Metadata never authorizes release and contains no secrets or private paths.

For managed apps, reserve early enough to reject before display startup: use a small worker reservation/handoff mode, then transfer to the host via authenticated parent-child acknowledgement while holding a separate named transition gate so no competitor can slip into the transfer gap. The reservation owner holds the transition gate, releases the acquisition mutex only for the designated child identified by an inherited one-use handoff ticket, and waits for that child to acquire and acknowledge. The designated child uses the ticket path rather than waiting on the transition gate; all other contenders must take the gate first. On cancellation the coordinator reacquires/settles ownership before opening the gate. The host acknowledges ownership before any input create; reservation is not released to competitors until host ownership is established or launch is cancelled. The same atomic helper guards worker acquisition. Panel preflight is advisory; the native acquisition check is authoritative. Update runtime freshness/capability checks so managed launches cannot use an older cached host that bypasses it.

A new direct/packaged host also participates at native acquisition, with a generic standalone owner label when no managed app metadata exists. Keep the existing full-host singleton for CEF/display safety; it is not the hand lease and the worker does not take it. Never use the full-host singleton to block input-free app launches.

**Limits:** older/uncooperative standalone binaries and unrelated software cannot be made to honor a new lease. Detect an already-running legacy full host conservatively and refuse worker Start with close/update guidance; this is not race-proof coordination with a legacy executable launched later. Concurrent legacy-host use is explicitly unsupported. No claim of cross-user/logon-session camera exclusion: that needs a machine broker/security policy and hardware validation later. Distinct panels/checkouts within the supported scope are covered, not just this panel's `runner.busy`.

On abandoned mutex acquisition, verify the recorded PID/creation identity is dead (or cannot still be an owner), clear stale advisory metadata while holding the mutex, and only then start. A slow heartbeat is never enough. Unknown process state fails closed. No implicit Stop, force-steal or owner expiry while alive.

### 3. Small input-only process and build boundary

Create a standalone `native/provider-session` CMake entry that builds `xrb-provider-session.exe`, fake-provider DLLs and focused tests **without configuring, linking, copying or initializing CEF, display or platform code**. Extract reusable loader/input bridge, QPC clock, hand serialization and neutral socket primitives from the current host only where required; both executables use that code. Separate the input built-in registry from desktop display registration. Keep existing DLL directory isolation, ABI checks, nonthrowing JSON discipline and unchanged app behavior.

The worker receives a bounded bootstrap/configuration through an inherited anonymous stdin pipe, not CLI credentials or a file. Panel resolves the owner-qualified registry entry and effective plugin settings through existing neutral resolvers; no app-specific manifest is required. Source/configuration and profile revision checks run under the existing preparation/source-write exclusion, with initial unique-real choice pinning using the existing state writer. Reject unsaved picker drafts; preserve explicit unavailable choices. Check actual selected plugin ownership/contained binary paths again before create, not arbitrary client paths. Use selected workspace plugin configuration/data paths as apps do, never core or another workspace.

Worker lifecycle: acquire/reserve lease -> load/create selected input -> start -> callbacks -> stop -> destroy -> unload -> release. Validate API size and required function pointers; preserve provider `last_error`/status/log reason in bounded sanitized messages. Start errors never silently degrade to no input. Images are explicitly disabled (`debugImages=false`); ignore/reject their callbacks with no image allocation. Do not mutate or inspect private source. No provider live-settings callback is invented: settings/source changes need Stop then Start.

A bootstrap/command stdin protocol supports Stop and reservation handoff; stdout contains bounded structured lifecycle/endpoint/lease events, with stderr bounded for logs. Secrets are never emitted. The loopback endpoint port can be public metadata; its capability is not. Build/rebuild/cache staging checks include the worker and protocol capability; an old or missing worker yields Rebuild guidance, never full-host fallback. Add worker distribution only to the panel runtime that needs it; app packages do not acquire an author-panel dependency.

### 4. Authenticated loopback and bounded newest-frame delivery

Reuse/extract the existing native loopback WebSocket implementation, but add an explicit session-authentication mode instead of its token-in-URL convention. Worker listens only on `127.0.0.1` at an ephemeral port. Panel mints separate high-entropy worker-control and page-observation capabilities per session; stdin carries worker credentials. Page receives only its observer capability in a no-store Start response. Credentials remain memory-only, never URL/query, logs, status, preferences, browser storage or build output.

Session route namespace: `/api/hands/session` for status/Start/Stop and a scoped bootstrap action for short-lived page control capabilities. Bootstrap requires the exact configured panel Host/Origin, same-origin fetch metadata and a non-simple custom header; deny cross-origin/absent-origin mutations, wildcard CORS and DNS-rebinding Hosts. Subsequent operations require the capability in an authorization header and matching panel/page/session identity. Browser scripts cannot obtain it through ordinary cross-origin forms/reads. These rules apply to the new session surface without widening preview CORS. Existing trusted same-origin code/local OS user is not sandboxed.

On the worker socket, validate the browser's exact panel Origin, role and an initial bounded authentication message within 2 seconds; send no status/frame before success. Panel observer/control uses its separate credential and expected process/session binding. Allow one owning page receiver and one panel supervisor connection, not arbitrary subscribers. Reject control messages from the frame-only receiver. Close/revoke credentials on retirement; a page reload requires a fresh explicit Start, not automatic camera reopening.

Envelope v1 carries source `{owner,id}`, unpredictable session ID, random epoch, safe increasing uint64-on-wire sequence, capture QPC ms, worker publication QPC ms, worker tracking rate and existing canonical hand payload/capability mask. JS validates sequence in its safe range; retire before exhaustion. No changes to the ABI or 456-byte hand. Control/profile/status bounds are 16 KiB/16 KiB/4 KiB; frame messages at most 128 KiB, with at most 255 hands matching the existing wire ceiling. A hand count above the ceiling is rejected, never silently truncated. No camera buffers.

Callback copies the validated bounded frame while borrowed memory is valid, under a short lock, into **one replaceable newest slot**. Network serialization/sends never run in a provider callback. Allow one frame in flight and one newest pending; the page acknowledges consumption at its frame boundary. No further frame is sent until acknowledgement, so browser/network event queues cannot accumulate at producer speed. Bound socket writes and close an unresponsive peer; status/clock/control have separate small limits. Track received/dropped/rejected counts without treating drops as no-hand detections. The page retains one newest admitted frame, not a work queue.

Validation happens in worker callback before copy, at transport decoding and at page adapter admission: struct/header/payload lengths, count/pointer consistency, all finite coordinates and signal fields, confidence in 0..1, legal handedness/flags/pinch bytes, duplicate hand IDs, capability masks, finite nonnegative tracking rate/times, correct identity/epoch and increasing sequence. Optional unsupported fields retain their published representation/capabilities; never manufacture native signals. Reject impossible or malformed payloads; fail visibly after repeated invalid frames. ABI pointer validity is a trusted-plugin obligation: bounds checks cannot sandbox an arbitrary invalid pointer; access violation becomes contained worker failure, not panel memory access.

### 5. Clocks, freshness and lifetime fencing

Use a small four-timestamp monotonic ping exchange between page and worker, lowest-RTT samples plus bounded refresh, to map worker QPC to page `performance.now()`. Panel wall time is not capture time. Preserve capture timestamp; publication/send time is separate. Record RTT/offset uncertainty in Stats. Before first admission require finite mapping with uncertainty no more than 50 ms; reject captures more than mapping uncertainty plus 50 ms in the future or older than 250 ms. These are initial conservative software admission bounds, not measured device latency promises.

A backwards capture clock, mapping discontinuity or excess uncertainty retires the adapter epoch, clears interaction immediately and requires new synchronization/epoch before more frames. Old in-flight frames cannot resume a hold. Inactivity beyond **250 ms** clears hands, visuals, filter/prediction/grace, gestures, pointer presses and target holds through shared SDK empty-input/reset semantics, without emitting click. Resume after a short stall starts clean; it does not blend across old input. Zero-hand frames immediately clear rendered hands/holds; do not let loss grace keep a test target held through explicit no-hand/stop signals.

Initial deadlines: Start 30 s; graceful worker Stop 5 s; owning page heartbeat 1 s with 5 s expiry; authenticated socket handshake 2 s; stalled stream warning/clear at 250 ms; no valid frames for 10 s after startup or during running ends the session with a reason. Empty valid frames count as healthy. A live provider status heartbeat does not make stale hand data fresh. Make timers injectable in tests, not user-facing arbitrary tuning.

The supervisor state machine is Not started -> Starting -> Running -> Stopping -> Stopped, with terminal Failed preserving reason. Internally hold the acquisition-unavailable state throughout teardown. Stop is idempotent and cancels pending Start; fence tokens/epoch before waiting for native cleanup. Stop accepts only the owning page/session capability, not whoever last selected that provider. A second tab sees busy and cannot adopt or terminate another tab's session.

Normal shutdown: reject new work -> retire admission/revoke credentials -> notify/clear SDK -> stop producer -> await callback quiescence -> destroy/unload -> release lease -> report Stopped. Crash, protocol fault and provider Failed use the same fence and terminal reason. If stop/destroy hangs, terminate only this contained headless child after the deadline, wait for its process handle to signal death, then permit recovery. If death cannot be established, stay Failed/busy with recovery guidance. No automatic retry and no force-kill of someone else's app.

Use a small native supervisor/launcher mode that opens the exact panel process handle, creates the worker suspended, assigns it to a kill-on-close Job Object and only then resumes it. The supervisor watches both that panel handle and its stdin pipe; panel death/EOF closes the job and it exits. This avoids requiring Node to manipulate native job handles or a spawn-before-job race. Panel-requested Stop first takes the graceful path; the job is the crash/hang backstop. Panel crash therefore cannot strand the child. Never put the person's running app/panel or unrelated processes in that job. A reservation/host handoff must keep ownership and containment correct until the host has acknowledged its own lease. Existing app shutdown keeps its clean display-exit behavior, not the worker's 5 s forced-cleanup policy.

Page `pagehide`/dispose sends best-effort Stop and closes its socket; correctness relies on socket loss, heartbeats and job containment, not unload fetch success. Browser suspension deliberately relinquishes the session after timeout. Tab switches within the page do not dispose the viewport or dirty forms. Panel shutdown awaits session cleanup before closing services; worker death/exit releases the kernel lease even if the panel failed first. Driver-level camera release after process death still needs hardware acceptance.

### 6. Existing SDK ingress, profile and interactions

Connect the authenticated transport to PR 51's source-neutral adapter, never the diagnostic boot module or another renderer. Valid applied PR 50 profile must precede first frame. Pipeline remains canonical validation/clock admission -> one profile geometry transform in `HandFrameIngress` -> default `HandInput` filtering/prediction/gestures -> shared scene mapping -> SDK interaction/pointer and standard visuals. Do not add scene group offset/scale or disable default filtering to make the viewer look responsive.

Use PR 50's full-snapshot profile sequencing and actual application acknowledgements with Hands session identity as the target, separate from frame sequence. Source Save never updates acquisition or profile drafts. Apply saves via the existing writer and delivers to the viewport as another active target, retaining accurate per-target saved/applying/applied/failed status. Geometry swap uses shared release/reset; appearance-only swap preserves holds. Acks match session, profile sequence and revision only after frame-boundary application. If a Hand-off app runs concurrently with Hands, neither target's acknowledgement may stand in for the other's. Dirty adjustment drafts are not rendered or discarded by session updates.

Keep settings controls, tabs and view tools from PR 51. In Source add content-sized Start and Stop using existing button/status primitives, and an active session identity if the saved picker now differs. Require Save before Start when picker is dirty. Synthetic can be explicitly selected and started through exactly the same session path, never a local fixture fallback. WebXR-only sources show unsupported-in-standalone-native-session guidance; never request XR/camera permission on navigation.

Compact provider-adjacent status/metrics (not new Output/Stats tabs) distinguish not started, starting, running with hands, running but no hands detected, waiting/stalled, stopping, failed with provider reason, stopped, unavailable and occupied. Tracking chip measures unique valid received source-frame sequences over a rolling second (including valid empty frames), not renderer updates, predictions, provider-declared Hz or app history. Keep reported provider Hz separate for diagnosis. Frame age is mapped capture age plus visible uncertainty; render chip remains actual renderer fps. Idle/Stopped/disconnected rates are unavailable, not a false zero or green running chip.

Add one small pinch target and one draggable object in the central scene with existing SDK interaction primitives; no new tab, fixture generator or raw native gesture handling. Display held/released/result state from shared interaction events. Reset targets on no-hand, staleness, stop, disposal and geometry reset; appearance changes do not alter them. Mouse orbit may still control the camera, but cannot count as a successful hand check. If UI Kit imports are needed, extend the existing explicit browser module allowlist minimally and test closure/path refusal rather than broadly serving source files.

### 7. Selected-provider recording contract (approved addition)

PR 51 owns recorder UI/storage/legacy playback. Coordinate the new format through comments on both PRs 51 and 53. Expose `subscribeRawFrames(listener)` with unsubscribe and `recordingSource()` from the authenticated live client. Deliver an owned copy of each validated unchanged HANDS v2 packet and source/epoch/sequence/capture/publication metadata **before** profile ingress/filtering; no renderer data or native capability loss. Lifecycle retirement finalizes/stops recording. No extra camera or provider process starts for Record.

New JSON format v1 has `kind:"xrb-provider-stream"`, `version:1`, `frameSpace:"panel-metres"`, `processing:"provider-published"`, `globalAdjustmentsApplied:false`, axes `x-right,y-up,z-viewer`, clock `windows-qpc-ms`, source owner/id/available version, original session/epoch and capture-relative timing. Samples retain original sequence/timestamps and base64 of the complete native HANDS v2 packet, preserving native signals, confidence and capability mask. No credentials, paths, images, global profile values or inferred calibration claims. Bound files to 16 MiB, 10,000 frames and 120 seconds; stop visibly at any cap. Delivered-frame gaps remain gaps, not a lossless-capture claim.

Replay validates the whole document and every packet, takes a fresh replay epoch, maps original capture deltas to page monotonic time and passes raw frames through the current applied profile/SDK once. It never reapplies a recorded global transform, since none was baked in. Require explicit Stop live before replay admission; label replay and provenance. Existing CSV/image/depth/paired formats keep their existing readers and coordinate labels with no migration or reinterpretation. Calibration capture requires a shared acquisition lease boundary and cannot feed selected-provider frames.

### 8. Platform boundary

Windows x64 is the only implemented/advertised worker platform in this change. Other platforms show an explicit unsupported-session reason rather than trying the Windows executable or falling back to synthetic/WebXR. Supporting them needs a portable input ABI/export/loading layer instead of the existing Windows-only DLL conventions, an OS-owned interprocess lock and owner identity, child-process containment/parent-death handling, monotonic-clock mapping, a native build/runtime inventory, and platform-specific fake-provider and device tests. Browser-only page rendering stays available without native startup; headset/WebXR hand acquisition remains the existing explicit XR-session app path, not this worker.

### 9. Isolated software evidence and person-run checklist

All runtime validation after approval uses a task-owned workspace/project root, profile and browser user-data directory outside this checkout, on a free port. Never attach to, restart or inspect the person's running panel, alter their global profile/projects, open real cameras, load installed private providers or download runtimes/models. Only the test-built fake input DLL and existing explicitly selected synthetic provider are allowed. No app/server/browser is needed for this planning step.

Each outcome lands its focused tests and relevant docs, not a final test dump:

- Lease: two processes/panels/checkouts racing app versus Hands, app reservation/handoff failure, Hand-off bypass, owner metadata failure, PID reuse, abandoned owner, slow live owner, reservation cancellation and legacy-host refusal; assert at most one provider create/open.
- Worker: CEF-free standalone build/link dependency check, fake ABI DLL query/create/start/error/no-hand/publish/stop/destroy ordering, concurrent callbacks/borrowed-buffer overwrite, malformed output, hung startup/stop/destroy, crash and callback quiescence. Run synthetic only as an explicitly selected ordinary provider.
- Service/transport: actual isolated worker/socket tests for role/token/Origin/Host binding, no credential leakage, replay/late epoch, malformed/oversize/future/backwards frames, slow consumer bounded memory, clock mapping/uncertainty, no-data deadlines, page loss, panel crash/job cleanup and process-death-before-reacquire.
- SDK/profile: equivalent frames and clocks through app and Hands yield equivalent processed points, gestures and visuals; exactly one transform; geometry Apply cancels holds, appearance-only does not, initial-profile gate, wrong/late acknowledgement and retired frames never act.
- Recording: exact raw packet round-trip including native signals and capabilities, no baked-in profile, frame/time/size caps, lifecycle stop, malformed provenance and replay once under a nonidentity profile; existing recordings unchanged.
- UI: default-window provider/adjustments and compact metrics states, real-frame fps/no-hand/error/occupied states, Start/Stop/dirty source/second-tab ownership, live pinch/drag through fake provider transport and Stop mid-hold. Screenshots record default browser outer/inner dimensions; responsive/theme checks supplement them. Preseeded unrelated preferences/calibration/recordings and project sources stay byte-identical.

Native PR checks may be skipped by current CI policy. Report actual standalone native build/test execution separately from TypeScript/browser checks; a skipped lane is not native success. The agent has **no camera, tracking runtime or hardware**, so device initialization, plugin data-path assumptions, physical axes/scale/calibration, native gesture feel, camera release/reacquisition, sustained physical fps and capture-to-display latency remain **unverified**.

Short checklist for the person after implementation, on their chosen machine with the normal updated runtime:

1. Open Hands: no camera starts. Save the intended real provider if needed, press Start, and note provider identity, startup errors, observed fps and frame age.
2. Show then hide both hands: verify position/handedness and that no-hands means an empty view, not a generated replacement; move again to check clean recovery.
3. Apply a recognizable offset/size/appearance change and compare against a normally rebuilt Hand-enabled app after stopping Hands. Check pinch and drag, including Stop and geometry Apply mid-hold.
4. With an app holding Hand, try Hands Start; then with Hands active try app Run. Both must name the owner, refuse the competitor and leave the owner untouched. Repeat from a second panel/checkout if used.
5. Stop, close the page, and close the panel in separate runs; check camera indicators turn off and the next explicit Start/app Run can reacquire. If a failure occurs, retain bounded reason/logs without credentials.

No checklist result is claimed by mocks. Physical failure returns to this same implementation PR as a repair, without changing/copying the private plugin as a shortcut.

## Risks / Trade-offs

- [Lease handoff races or parent death releases ownership early] -> common native transition gate, host acknowledgement before reservation release, contained children and process-level race/crash tests; never a panel-only lock.
- [Older hosts or other logon sessions bypass coordination] -> managed runtime capability gate and legacy-host refusal; explicitly unsupported concurrent legacy/cross-session use rather than a false machine-wide guarantee.
- [Provider hangs or violates borrowed-pointer rules] -> immediate bounded validation/copy, isolated native process, stop deadline and job containment; trusted ABI is not a memory sandbox.
- [Local socket is mistaken for authentication] -> distinct in-memory capabilities, exact Origin/Host checks, first-message authorization and no URL credentials; untrusted web pages cannot open cameras through new routes.
- [Frames continue holding input after loss] -> freshness timer independent of arrival, epoch fencing and shared explicit release/reset; test held state across every discontinuity.
- [Viewer diverges from apps or duplicates adjustments] -> consume delivered 50/51 seams and compare equivalent pipeline traces; do not add raw options or visual transforms.
- [Native refactoring grows into host rewrite] -> extract only clock/serialization/input/socket dependencies needed for the independent worker, retain host ABI/channel behavior and focused compatibility tests.
- [Camera cleanup appears certain from fake tests] -> report unverified driver/runtime behavior plainly and require the short machine checklist; no physical performance claim.
