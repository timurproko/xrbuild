# Published local removal implementation

Policy: [Shared delivery rules](delivery-rules.md), especially R12-R16, using only the `xrbuild` entry in
[Delivery adapters](delivery-adapters.json). This page documents repository command/API details and incomplete wiring.

## Current entry points and prerequisite

`pnpm worktree remove <name> [--expected-head <sha>]` uses the exact published-local engine in
`tools/worktree/published-removal.mjs`. The optional expected head binds a previously observed snapshot. Branch refs
and remote resources are retained. The engine does not query PR readiness, CI or acceptance for this local-only route.

**Trusted cleanup ownership wiring is not yet released/verified.** The default CLI reports an unavailable ownership
adapter and preserves the checkout. It does not infer ownership from clean Git, a detached session or a caller's
`--owned` assertion. No such assertion flag is provided. The programmatic `removePublishedCheckout` API takes a
trusted `readClaims(context)` oracle returning a target-bound available state and generation; that observation is
re-read before disposal. The fixture registry in tests is not a deployed runtime claim provider. Ordinary Git use
outside the optional helper remains independent of A1 installation.

The current `.a1/worktree.json` is a legacy bulk-sweep declaration, not a compatible exact-completion adapter.
Task 3.3 in PR #19 remains incomplete until a compatible runtime is released and its actual interface is verified.
There is no complete/discard/sweep substitute, guessed schema or runtime-owned deletion implementation here.
Legacy `--discard` is recognized but blocked as a separately unsupported operation; it never silently deletes local
refs or remote work. CLI force/ownership overrides are rejected.

## Checked content and metadata inventory

Inspection uses plain canonical paths, registered linked-worktree identities, index/HEAD agreement and actual
bounded source reads. Cached attributes supply text normalization; binary and unpublished bytes are not hidden by
stat caches or `assume-unchanged`. No working-tree-recursive Git status operation is needed to establish cleanliness.
All source directories/files are accounted for without following links. Physical identity and content fingerprints
are checked again, as are repository identity, live remote containment and claimant generation. Physical IDs use
BigInt-derived strings and nanosecond birth times so Windows 64-bit inode values are not rounded through Number.

No ignored/cache payload is admitted for automatic disposal in this checkpoint. This includes `node_modules/`,
public dependency junctions, build output, `.artifacts/handoff.json` and other scratch, even if generated by repository
tools. Unknown content must be separately reviewed/preserved rather than deleted by this command. Private workspace
and KEEP markers block before their contents are inspected. Nested Git metadata, gitlinks, configured submodules,
links/hardlinks, Git locks and unfinished/unknown Git state are protected. A tracked regular `.gitmodules` file alone
is not classified as an actual nested repository.

The linked `.git` pointer and these Git-generated administrative paths are admitted: `HEAD`, `index`, `commondir`,
`gitdir`, `logs/HEAD`, `ORIG_HEAD`, `FETCH_HEAD`, plus an empty `refs/` directory. Recovery refs/reflog entries must be
ancestors of the current HEAD. `COMMIT_EDITMSG` is admitted only when it exactly matches the current commit message;
unpublished drafts remain protected. Other administrative files/directories (including personal worktree config,
rebase state, nested storage or unknown payloads) block. Entry, depth, byte/file-size and recovery-reference bounds
fail closed; implementation limits can be tightened but not disabled or increased through the API.

## Journal and partial recovery

Tool-owned common Git metadata under `.git/xrb-removal/` holds one scoped lock and create-only journal per canonical
target. This is not agent scratch, publication/acceptance evidence or cleanup enrollment. The journal records the
physical checkout/admin identities, exact branch/head and content fingerprint before the single non-force
`git worktree remove -- <target>` operation. No recursive/force fallback, process termination, private export or
branch deletion follows it.

Prepared records can be reevaluated only against the same checkout/content, with fresh publication/claim checks.
Uncertain `removing`/`partial` records require explicit recovery instead of automatic retry deletion. Completed
records can report an already-absent target without another removal; any recreated path is retained. Unknown,
linked, modified or incomplete journals/locks are never cleared to make a retry pass. Journal generations are not
automatically reset for directory-name reuse; preservation/recovery needs separate reviewed handling.

Explicit `sweep --apply` still selects only merged candidates, rechecks that eligibility, and calls this same engine.
It retains refs and reports blocked candidates independently; it gains no open-PR removal authority or runtime role.
Without the trusted ownership prerequisite it cannot remove even a merged clean checkout.

## Verification boundaries

`tools/worktree/published-removal.test.mjs` uses isolated disposable Git repositories, real non-force Git operations
and a synthetic claimant registry. It checks remote descendants/offline evidence, each shared preservation hazard,
normalization/stat-cache defenses, recovery history, journal/recreated-resource safety and missing-runtime blockers.
Live runtime adoption remains task 3.3. Offline proposed-interface verification below is separate from release
compatibility, final-head CI and device acceptance.

### Generation requirement resolved as an implementation choice

The shared rules require verifiable ownership/preservation, not an A1 field named generation. The legacy standalone
`readClaims(context)` observation path remains intact. The new inactive route instead uses
`withSessionClaimSnapshot(directory, options, callback)` on the same gate as A1's attachment writers, and calls
`sessionWorktreeClaimState(commonDir, gitDir, options)` under that exclusion. Absence is not relabeled an available
generation. An unforgeable in-memory scoped capability binds the actual gate lifetime and checkout/admin identity;
serialized owner flags, copied objects, expired scopes and other-target scopes are rejected. No token is fabricated
from a PID, timestamp, inventory row or private claim record.

Real preflight creates a bounded, create-only journal reservation binding the original head, physical identity,
content fingerprint and operation/selectors before detach. Async scoped execution retains all existing preservation,
publication, Git-lock and non-force-removal checks, rechecks ownership under the gate, and journals uncertainty.
The final Git child is asynchronous so the lease holder can service heartbeat/loss checks. Both prepared declarations
are exact-target: `localRemoval.preflight/execute` and `cleanupPreflight/cleanup`. Merged completion requires the exact
merged PR/change/head plus its squash merge commit contained in live main; a deleted source branch is not recreated.
Both routes retain all local refs and remote resources. No route falls back to a sweep or force removal.

Ten integration tests now cover real successful local and squash-merged removals, retained refs, unrelated merged
checkouts, actual cross-process contention, acquisition after runtime precheck, ignored/new content, reowned/published
heads, recreated identities, changed declarations, expired/misbound scopes and replaced gate resources.

### Specific remaining upstream capability: child-lifetime loss fencing

Current `claim-gate.ts` uses a 10-second stale-reclaimable filesystem lease with `onCompromised: () => {}`.
`withSessionClaimSnapshot` exposes a callback, but no loss-aware child-lifetime exclusion guarantee. This is not a
missing generation API. A non-destructive integration probe actually suspends the isolated holder's event loop for
14 seconds: a second OS process then acquires through the real A1 APIs while the original callback has not returned.
XR detects the lost lease and refuses before removal. The gate-replacement test likewise preserves the checkout.

The inactive bridge checks actual gate identity/freshness, invalidates expired capabilities, and cancels its own
in-flight Git operation on observed loss, leaving a recoverable journal. Those checks cannot run while the holder
is suspended. If its destructive child were already running, the present API cannot guarantee that a new owner
will not be admitted first. Successful normal-path tests are therefore **not** a live loss-fencing certificate.

Minimal upstream requirement: atomically verify the target is unclaimed and keep attachment writers excluded until
the cleanup child has finished or is proven stopped, including holder suspension/death and gate loss. Use a
non-reclaimable child-lifetime authority or equivalent fencing; merely adding a nonce/generation, increasing the
stale timeout, or notifying the suspended parent after takeover is insufficient. Expose that scoped execution/loss
contract through the existing facilities or a cleanup-specific wrapper; no particular new method name is required.
A1 still executes repository cleanup rather than deleting files itself.

The prototype CLI remains unavailable and the deployed `.a1/worktree.json` is unchanged. Task 3.3 stays unchecked
pending that capability/compatibility verification and a compatible release. No minimum release or live adoption is
claimed. There is no legacy sweep fallback.
