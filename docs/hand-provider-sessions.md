# Live Hands and native acquisition ownership

## Using Hands

Opening Hands starts no device. Choose the desired Skeleton provider in the **Setup** tab (the choice saves immediately; only installed trackers are listed), then use **Start** at the left of the viewer toolbar; the session status shows in the header centre. The same button becomes **Stop**. Compact feedback distinguishes startup, waiting, running, valid empty detections, stalled input, teardown, failure and stopped. Another page/app's owner is never implicitly stopped. Changing the saved provider does not change active acquisition; its old identity remains on the compact chip when different.

The hand-tracking chip counts unique admitted source results in the last second, including empty frames, not renders, prediction samples, app history or provider-reported rate. Hover it for mapped capture age/uncertainty, delivery gaps and separately reported Hz. Unavailable/stale rates show a dash. Renderer fps remains independent. Standard SDK drawing keeps its existing two-human-hand display capacity; transport, ingress and raw recording validate/retain the wire's complete up-to-255-hand data rather than truncating it.

The viewer shows one object (cube, sphere or Suzanne, chosen in Setup) in front of a monitor frame sized from the Monitor resolution. Pinch or grab picks it up; it follows the hand and turns with the palm, using SDK interaction events from current live hands only; camera orbit/mouse cannot count as a hand check. Holds reset on no hands, stale input, geometry changes, Stop and disposal; appearance changes preserve a hold. Hands are drawn where they physically are relative to the frame; the Transform offset changes only what apps receive. Transform and Display edits, presets and slider drags commit immediately through the shared profile pipeline; diagnostics and provider start/stop events appear in the **Log** tab.

Windows x64 native Hand runs reserve a single acquisition slot before starting a development server or opening a display. The slot spans all providers, workspaces, panels and checkouts for the current Windows user/logon session. Different provider names can refer to the same cameras, so the initial policy deliberately does not allow concurrent native sources.

A busy message names the owning app or Hands session. A different live Hands page in this panel offers Take over: this explicit authenticated action drains the designated old worker before starting here. An app or a different panel still needs owner-directed Stop; no arbitrary PID control or unauthenticated cross-panel shutdown is exposed. Nothing steals an OS lease because a heartbeat expired. Hand-off apps and standalone browser XR sessions do not take this native slot. Source and provider settings remain launch snapshots; no provider live-settings ABI is added.

## Ownership and launch handoff

The acquisition process holds a secured named Windows mutex. A separate transition gate protects managed launch reservation/handoff. Advisory metadata contains only a bounded display label, process ID and creation identity; metadata is not authorization to release ownership. Both objects are scoped independently of repository or workspace paths. Process death releases the OS mutex. An abandoned owning thread in a still-live or inaccessible process is not safe recovery: stop that process first.

`xrb-acquisition.exe` is a small CEF-free reservation helper. The panel supplies a random one-use handoff ticket through stdin. The new host receives it through its process environment (not arguments, URLs, saved settings or logs), authenticates to the private local named pipe and acquires the slot while every other contender remains behind the transition gate. The helper verifies the designated process identity, receives its acquisition acknowledgement and ends. The host clears the environment ticket before creating providers or browser children. Cancellation closes the reservation, and no late launch is allowed to continue. The handoff helper never loads a provider or opens a device.

New direct and packaged hosts also acquire the slot before input creation and display startup. The full host's existing singleton remains in place for display/CEF safety; it is not used as the hand slot. Legacy executables and unrelated applications cannot be made to cooperate retroactively. Running an old host concurrently with a new provider session is unsupported. Cross-user/logon-session arbitration needs a separate machine-wide broker/security policy and is not claimed here.

The native helper belongs to the selected immutable runtime next to the host; it is built by normal Rebuild host, and helper source changes invalidate the normal host fingerprint. Before reserving or starting an app, the panel also checks the host's existing passive `--list-plugins` inventory for `handAcquisition:1`; a helper file alone does not prove the host participates. A managed Hand run with an old/malformed inventory or absent helper fails with Rebuild guidance instead of using an unprotected old runtime. Offline app packages still require no author panel; their updated host can acquire the slot directly without the reservation helper.

## Standalone build and focused checks

The acquisition helper and tests configure independently of CEF, displays and plugin runtimes:

```text
cmake -S native/provider-session -B native/provider-session/build -G "Visual Studio 17 2022" -A x64
cmake --build native/provider-session/build --config Release
native/provider-session/build/Release/acquisition-tests.exe
```

The optional `XRB_TEST_ACQUISITION_HELPER` and `XRB_TEST_ACQUISITION_CHILD` test variables point to `xrb-acquisition-test.exe` and `acquisition-tests.exe` in that build. They enable the actual cross-process handoff test in `packages/control-panel/test/hand-acquisition.test.ts`. The test-only helper requires a random isolated namespace and cannot acquire the person's normal slot. Ordinary tests use fake transports and do not require hardware or installed private providers.

## Input-only worker

The same standalone build now also produces `xrb-provider-session.exe` without CEF, display or platform initialization. It reuses the neutral DLL loader, input ABI bridge, existing Synthetic/Replay implementations and unchanged HANDS v2 serialization. It checks the selected binary identity and complete input function table. Borrowed callbacks are validated and copied into one owned newest-frame slot; malformed values never enter that slot. Confidence zero and finite zero-filled optional fields are valid; non-finite joints/confidence and confidence outside the ABI's 0..1 range reject that hand, not valid peers. An all-rejected safely timed observation clears hands as a marked dropped observation, not a genuine zero-detection claim. Unsafe headers/pointers are dropped without dereferencing or inventing a timestamp. A recent 10-second rejection window resets on healthy output (including genuine empty detections or intact peers); at least three recent rejected callbacks sustained across that window fail with a clear reason, never three lifetime errors. The visible diagnostic line retains rejected kind, joint index or n/a, and counts after recovery/failure, without raw poses or private data. Actual device score distributions remain unmeasured; no undocumented scale is clamped or normalized. Optional native capabilities and all published hand bytes remain intact. Debug images are disabled.

Bootstrap and Stop are bounded stdin messages. The worker opens the exact parent process handle and observes stdin loss; graceful shutdown stops input, awaits callback quiescence, destroys and unloads the provider, then releases acquisition. A watchdog contains hung start/stop/destroy by ending this worker only, not any app or foreign panel. Test-only timers and mutex namespaces are compiled into a separate test executable, never the production worker. The session service supplies authenticated controls, worker transport and supervisor job containment; page controls and SDK/recorder integration consume its dedicated client. Lifecycle stdout is never pose input or a browser frame API.

`prepareHandSession` checks current profile/registry revisions and the saved source before any acquisition, pins only the already-shown unique-real initial choice through the existing writer, snapshots selected global provider settings, and refuses unsupported sources, unsafe/missing runtime files or changed ownership. The native worker derives `xrb.dataDir` through the very same `logx::dataDir()` function as an app host, rather than overriding the provider's existing calibration/data lookup. New core state remains workspace-owned and no private source or calibration is imported. The actual private provider's data-path/runtime assumptions still require the physical-machine check; a missing prerequisite must remain the provider's visible error, not trigger fallback or migration.

Set `XRB_TEST_PROVIDER_WORKER` to `xrb-provider-session-test.exe` and `XRB_TEST_PROVIDER_DLL` to `xrb_session_test.dll` to run `hand-provider-worker.test.ts` against the test-built ABI DLL and explicitly selected Synthetic. `provider-frame-tests.exe` checks exact raw layout, borrowed-buffer lifetime, invalid output, empty detections and concurrent callback sequences.

## Authenticated session service, transport and containment

Create/start failures keep the provider's own diagnostic even if shutdown precedes the control reader's first read. The reader observes persistent cancellation while polling its owned stdin pipe; shutdown does not rely on a one-shot cancellation reaching an already pending read. Native regression checks force that ordering without lengthening the startup/stop watchdogs.

The worker's loopback WebSocket uses `/hands` with no URL credentials. Its immutable bootstrap supplies the exact panel Origin, a 64-hex observer capability and 64-hex epoch; a client must authenticate with one masked binary UTF-8 capability message before receiving data. Wrong Origin/Host, wrong capability and concurrent receivers are refused. Client control messages are bounded; sockets time out rather than accumulating indefinite work. One frame may be in flight plus one replaceable newest pending frame. The browser must acknowledge consumption, not mere receipt.

Transport layout for the page client: the existing 16-byte channel header has type 21/version 2 (or type 23 for an explicitly filtered observation, excluded from unchanged raw recording; diagnostic-only empty observations do not count toward detection fps, while intact admitted peers do), followed by 64 ASCII epoch bytes, little-endian u64 source sequence, and the complete unchanged HANDS v2 packet. A consumption ACK is byte 110 plus the outer header's little-endian u32 transport sequence. Clock ping is byte 111 plus f64 page-send time; reply type 22 contains echoed page-send, QPC receive and QPC send as three little-endian f64 values. `hands-session-wire.js` validates every envelope and packet before SDK admission, including raw flags before decoder normalization, all 255 possible hands, numeric fields, identities and safe increasing sequences. Four-timestamp samples map QPC to page monotonic time using bounded lowest RTT samples: uncertainty must not exceed 50 ms, capture age must not exceed 250 ms, and future tolerance is uncertainty plus 50 ms. Backwards clocks or mapping discontinuity retire the session; stale input clears without becoming an empty-detection claim.

`xrb-provider-supervisor.exe` creates the worker suspended and atomically assigns its kill-on-close job at process birth using the Windows job-list creation attribute. It inherits only the three intended pipe handles, verifies containment before first resume, and watches the exact owning panel process handle. Launcher death cannot leave a resumed or suspended uncontained worker. Both graceful completion and forced launcher loss are exercised with isolated fake/synthetic processes and actual sockets. No display host or unrelated process belongs to this job.

Set `XRB_TEST_PROVIDER_SUPERVISOR` to the supervisor executable to include actual job-containment tests in `hand-worker-transport.test.ts`. These tests also reject foreign/bad authentication, prove no frame FIFO before consumption ACK, preserve source gaps and exercise clock replies.

`/api/hands/session/bootstrap` requires the exact configured Host/Origin, same-origin fetch metadata and a non-simple header. Subsequent session status, Start, Stop, heartbeat and profile acknowledgement operations require a memory-only page capability. Ordinary Stop/heartbeat/ACK remain owner-bound. Explicit same-panel Take over binds the currently observed session ID, drains that designated worker, and refuses stale/simultaneous ownership targets rather than replacing a new winner. Recover can drain only the owning page or an already failed/cancelled/expired session, not another live page. No session route joins preview CORS. Start reserves through the legacy-host guard and transfers ownership to the designated job-contained worker before input create. Stop fences the page first and waits for cleanup or verified child death. The supervisor forwards controls, gives graceful teardown six seconds, then terminates only its contained job and joins the exact worker handle for up to five seconds. Only complete bounded worker lines are forwarded, so forced termination mid-JSON cannot corrupt the supervisor's joined receipt. Its receipt plus launcher close gates lease release. If the launcher crashes or loses that receipt, a bounded read-only helper compares the recorded worker creation identity and joins that exact process; it never kills or signals a queried/reused PID. Numeric PID reuse alone is not death evidence. Stop and exact-identity verification cache only in-flight work, never a finished unsuccessful attempt. Stop, Recover, explicit Start/takeover and reload can recheck the same recorded identity after a timeout or transient failure, releasing exactly once when death becomes verifiable. A closed launcher is not written to or killed again. Background retries are throttled; panel shutdown/restart keeps its close operation in flight and retries until cleanup is verified, so the server cannot cache an unsuccessful close as success. After capability rotation the client uses authorized stale-session Recover rather than replaying an unauthorized Stop forever. The service allows 13 seconds before its last containment fallback. Client requests are bounded and reconcile lost replies; terminal notification follows local retired-context cleanup. Unresolved teardown shows retryable cleanup, not permanent Stopping or an unsafe enabled Start. Page heartbeat expiry is 5 seconds; socket loss, panel shutdown and actual parent-process death also stop the owned child. If cancelled preparation exceeds Stop's bounded drain wait, ownership remains busy while that preparation is alive; when it eventually resolves or rejects, no-child cleanup still releases exactly once and permits explicit Start without a panel restart. Tests cover delayed preparation/cancellation, owner refusal and real process/socket teardown. The authenticated client now feeds the delivered SDK viewport. Initial and updated profiles resolve only at a renderer frame boundary, then the owning session acknowledges the ordered envelope. App and Hands acknowledgements are tracked independently; one cannot claim another target is Applied. Geometry resets clear filters/visuals/SDK interaction; appearance-only updates preserve holds. Explicit empty frames bypass SDK loss grace, and an independent 250 ms freshness timer clears stalled input without clicking. Fresh input recovers Stalled without restarting. Several stale observations cannot terminate through a lifetime or three-frame counter; ten seconds without fresh usable input ends acquisition through the same verified teardown path. Startup/waiting, rejected output, transport/clock absence and owned cleanup remain distinct from a genuine empty detection. Dash fps never proves that a camera has been released. Default SDK ingress, smoothing, prediction, gestures, scene mapping and standard drawing remain unchanged.

Page control capabilities expire after 60 seconds without renewal. A separate random tab-continuity proof, never a control capability, is kept in tab-scoped session storage for top-level reload (iframes remain memory-only). Bootstrap rotates it and the capability, revokes the old document and drains its bound session before returning. A copied tab proof on an ordinary new navigation does not silently adopt or stop another live page. If storage is unavailable, memory-only renewal and explicit safe takeover remain available; expired page heartbeat cleanup still drains lost documents. No proof is saved in a profile, URL or log. An expired owner is retired before reauthorization: its socket, SDK hands/holds and timers are cleared, and the service cancels its old acquisition. The page obtains one fresh memory-only capability and retries only status reads, not Start/Stop/ACK/heartbeat as a different owner. Recovery never auto-starts capture or adopts another page's session; a new explicit Start works without reloading. Start automatically drains same-page or failed/dead same-panel leftovers before reservation, never labels its own cleanup as another-page Busy, and refuses a still-draining preparation without claiming devices are free. Delayed replies/errors from retired credentials or sockets cannot affect a replacement session.

## Optional session-owned mesh

Explicit Hands Start also allocates a run-owned authenticated mesh gateway, including with None (no processor).
The initial mesh choice/settings are pinned with the source/profile snapshot. Optional runtime validation and
preparation run asynchronously and cannot delay provider startup, skeleton sampling or interaction. Mesh never
reserves the camera lease. The existing post-processing GET/PUT and revision/run-bound retry routes target this
Hands owner when it is active, just as they target a managed native app. Idle saves start nothing.

Only the authenticated owning page receives `handMeshRuntime`; foreign page status, public post-processing
metadata, profiles and recordings contain no descriptor/credential. Stop, reload, heartbeat/page loss, provider
crash and panel exit retire the gateway and drain its separately contained processor. Failed mesh cleanup remains
visible and retryable and blocks mesh reuse, but does not retain the provider's camera lease after verified
provider death. No mesh failure substitutes another source or resets skeleton interaction.

The optional-process reuse fence is shared by Hands and managed apps in this panel, in both transition
directions. Releasing provider ownership is not proof that its optional tree ended. Every retired mesh owner
stays recorded until exact-tree termination is verified; pending joins coalesce and failed joins remain retryable.
A replacement consumer can start its skeleton and processor-free gateway immediately, but the processor-start
hook cannot launch through that fence, including after a settings Apply or Retry. Failed verification reports
an independent mesh failure; verified cleanup permits the latest requested generation without restarting input.
Stopping a new gateway revokes its credentials immediately even while an older tree is joining. Panel exit starts
both retirements and stops input owners before waiting for optional verification.

## Raw recording hooks, without recorder UI

`handsPage.session` exposes `recordingSource()`, `subscribeRawFrames(listener)` and `subscribeLifecycle(listener)`. Each raw listener receives its own unchanged HANDS v2 packet and decoded convenience frame before profile ingress; geometry/filter/render output is never recorded. `hands-provider-format.js` supplies bounded version-1 validation and replay; `createProviderRecording` supplies the raw capture helper. The simplified page does not mount a recorder UI.

The format is `kind: xrbuild-hand-session`, version 1, `frameSpace: panel-metres`, `processing: provider-published`, `globalAdjustmentsApplied: false`, clock `windows-qpc-ms`, axes `x-right,y-up,z-viewer`. It contains whitelisted source identity/version (`core`, `workspace:<id>` or the catalog's `bundled:<id>`), original session/epoch, a frozen validated portable recording-start profile, and capture-relative samples with original sequence/capture/publication timestamps plus base64 of the complete original packet. Credentials, paths, images and unknown metadata are rejected. Caps are 16 MiB, 10,000 samples and 120 seconds. These are delivered frames with explicit sequence gaps, not lossless capture.

Replay validates the whole file and every raw packet, owns a copy, takes a fresh replay epoch, applies only the recorded profile and maps original capture deltas to page time before SDK ingress. It refuses active live input and is labelled replay; the current live profile is never additionally applied. Existing CSV/image/depth/paired readers remain unchanged. Software tests compare app-default ingress, scene mapping, gestures and standard visual instances and verify raw-byte round-trip under nonidentity geometry. Hardware equivalence is still unverified.

### Provider data lookup: compatibility decision

The module passes app-compatible provider metadata, including the existing local-app-data `xrb.dataDir`, `exeDir`, owning `pluginDir`, 3D view and disabled debug images. There is no data-root override, copying, calibration reset or migration. Profile, recording and session core state stays workspace-owned. Test executables retain their explicit isolated configuration instead of looking up the person's app data. No device/runtime startup, physical camera release or latency result is claimed by these software tests. Other platforms need their own native loader/ABI export layer, OS-owned interprocess exclusion, child containment, monotonic clocks and device validation; they must not emulate success with Synthetic or silently enter XR.

## Person-run hardware checklist (not yet verified)

1. With the normal rebuilt runtime and intended real provider installed, open Hands: no camera starts. Choose it, press Start, note the identity, observed fps and capture-age tooltip, and copy the visible rejected-kind/joint-index/count line and any bounded failure/timeout reason.
2. Show/hide both hands: check handedness, axes, scale and empty detections; no generated replacement or old hold should remain. Move partly out of view and back; a dropped observation must remain non-fatal, clear any lost hold and recover. If Stalled persists, wait for its bounded clean stop and ensure the next Start reacquires without Busy on its own leftovers.
3. Change position, size and appearance; compare against a normally launched Hand-enabled app after stopping Hands. Pinch the sphere and move the cube. Check geometry edits and Stop mid-hold release without a click; appearance alone should not release.
4. Test app-to-Hands and Hands-to-app contention (and another panel/checkout if used). The competitor must name the owner without implicitly touching it. A second Hands page in the same panel must offer explicit Take over and join the old worker first; apps and different panels retain owner-directed Stop. Hand-off apps must remain usable.
5. In separate runs, Stop, close the page and close the panel; confirm camera indicators turn off and the next explicit Start/app Run reacquires. Also reload during acquisition: the old worker must end, reload must remain passive and the next explicit Start must reacquire. Browser suspension deliberately relinquishes ownership after timeout. Do not infer physical camera release or latency from software-only job tests.

Only an isolated test-built ABI DLL and explicitly selected existing Synthetic were exercised. Actual private-provider startup, calibration/data-path assumptions, driver release/reacquisition, native gesture feel and end-to-end latency remain unverified. No private provider, calibration/profile or person's running panel/project was used, migrated or copied.
