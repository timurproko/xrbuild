# Desktop hand mesh sidecar protocol

## Negotiated v2 observation contract

Version-one declarations and packets remain supported unchanged. Version-two declarations opt in with `capabilities`, using the exact names `final-pose-observations-v1`, `live-configure-v1`, and `preparation-progress-v1`. Unsupported or duplicate names are rejected. A modern consumer offers `{protocolVersion:2,capabilities:[...]}` on `/connect`; a legacy 204 response keeps the consumer on v1. A v2 response identifies `protocolVersion`, negotiated `capabilities`, `runId` and `settingsGeneration`. The native bootstrap remains `{version:1,url,token}`.

V2 frames/results include `version:2`, `runId`, and `settingsGeneration`, independent of pose `revision`. Each final-pose hand has `observations:{confidence,supported,ageMs}`: three aligned 21-element arrays. Entries are provider confidence (not calibrated probability), current support (`score > 0` for the existing acquisition contract), and age at `sampleMs` since the last supported mapped capture. Unknown entries are null, never fabricated confidence one or age zero. Prediction does not refresh capture evidence; zero confidence preserves the last supported age. These facts never gate or modify skeleton interaction. Legacy processors receive only the original positional frame shape.

A v2 processor receives the modern `start` and echoes its run/generation and declared capabilities in `ready`. Invalid negotiation fails mesh only. New observation requirements cannot be met by a legacy consumer: it gets rebuild/relaunch guidance, not invented evidence. The sections below describe the retained **v1** contract; modern configuration/preparation extends it as documented below.

## Modern configuration and generation association

A run keeps its loopback gateway/credential through processor replacement or None. A managed native Hand launch gets this gateway even with None, but no processor is started until selected. The server control API is `HandMeshRun.configure(pluginOrNull, values, savedRevision)`, `retry()`, `unavailable(savedRevision)`, `state()`, and `stop()`. Configure is asynchronous; callers persist first. There is at most one applying and one newest pending transaction. Any new None/selection/setting/device request preempts outstanding startup or repreparation: its old ACK and launch validator are retired immediately, and bounded owned-stage Stop/EOF/forced cleanup starts without waiting for the old preparation deadline. Even a validator that has not returned cannot block a newer control or spawn later. Only the newest pending target starts after verified cleanup, behind the same gateway/input session. An ordinary already-ready live setting still uses its bounded configure/ACK path without restarting the processor. None is reported as applied only after cleanup, not merely when queued. Mesh-only changes never release grabs or reset skeleton filters.

V2 settings declare `changeMode:"live"|"reprepare"` (default reprepare). A private configure packet is `{type:"configure",version:2,runId,owner,id,settingsVersion,settingsGeneration,savedRevision,settings,mode:"live"|"reprepare"}`. A successful acknowledgement is `{type:"configured",version:2,runId,owner,id,settingsVersion,settingsGeneration,settings}`. It must echo exactly the validated full values, schema, identity and generation, after an atomic frame-boundary application. Every declared setting must be its own explicit field, including false/zero/default values; missing fields or an absent settings object are rejected. Declaration defaults are used only for configuration input, never filled into applied evidence. `ready` for v2 startup echoes those same identity/settings fields plus declared `capabilities`. Pipe-write success is not applied evidence. Stale/duplicate ACKs cannot advance state; invalid identity/value ACKs fail mesh only. Legacy processors/consumers keep launch-time settings with honest unsupported/relaunch feedback rather than a fabricated live ACK.

Every authenticated frame response, including HTTP 204, carries `x-xrb-mesh-state` JSON (exposed through exact-origin CORS), as well as the legacy status header. State is `{runId,phase,reason,progress,step,requestedGeneration,appliedGeneration,drawingGeneration,savedRevision,owner,id}`; unavailable evidence is null. Connect also returns this as `state`. Settings generations increase monotonically per run, independently of pose/geometry `revision` and saved revision hashes. A newer requested generation immediately retires previous output/topology. Service and SDK reject late old-generation results even if their pose and topology label match. The SDK reports `drawingGeneration` only when a current validated mesh is returned for standard drawing and matches received service evidence; readiness, no hands or an unattached/disabled standard visual is not drawing evidence. Its state getter expires evidence against the local 33-ms pose clock even without further responses/renders, and clears it on non-drawable output, visual opt-out, invalidation, transport failure and disposal.

The existing panel post-processing save route reconciles committed values into its compatible managed desktop run and returns delivery separately from persistence. GET includes `delivery`; POST `/api/hands/postprocessing/retry` requires current `{runId,revision}` and cannot target another/retired run. None stops only mesh. Failed optional delivery preserves saved choices and input. No idle navigation/save starts a provider or processor. Explicit standalone Hands sessions now own the same gateway/control contract, with initial settings pinned at Start and owner-only descriptor delivery. Their optional preparation and processor cleanup are independent of the provider's camera lease.

## Modern preparation and failure packets

V2 declares integer `preparationTimeoutMs` from 1,000 through 120,000 ms (default 30,000). Startup and every reprepare get one hard allowance; live configure has a separate two-second ACK deadline. Progress cannot renew any deadline. Existing 33-ms result freshness and two-second executing-frame watchdog apply only to dispatched work, not model/device preparation. App attachment remains thirty seconds after app startup. The unattached overall cap is `max(90,000, preparationTimeoutMs + 60,000)` ms from gateway startup, at most 180 seconds; consumer heartbeat cleanup remains independent while Preparing.

A capable processor can emit `{type:"preparing",version:2,runId,owner,id,settingsVersion,settingsGeneration,progress,step}` while its matching startup/configure is outstanding. `progress` is null or finite 0..1; `step` is optional/null or exactly `runtime`, `assets`, `models`, `device`, or `warming`. State exposes these facts without forwarding arbitrary plugin log text or paths. Invalid/foreign control messages fail mesh only; stale-generation progress is ignored. Reprepare suspends incompatible output while the skeleton/input session and run gateway remain active; only exact `ready`/`configured` acknowledges usability.

Explicit failure is `{type:"failed",version:2,runId,owner,id,settingsVersion,settingsGeneration,reason}`. `reason` is one of `configuration-rejected`, `preparation-failed`, `runtime-unavailable`, `unsupported-setting`, mapped to bounded neutral core text. Do not send logs, model names, stack traces or paths. Timeout/failure preserves saved desired values, clears mesh and drains unusable processing; retry is explicit, never an automatic crash loop.

## Legacy v1

Only a panel-managed desktop run with Hand starts one selected mesh sidecar. It is optional: acquisition and interaction never wait for ready or results. Settings are pinned at launch; changing them or selecting None takes effect next run. Other execution contexts get no endpoint. No program, environment or model is installed or downloaded by this protocol.

## Contained process ownership (all versions)

Windows managed runs require checked `xrb-mesh-supervisor.exe` beside the selected host runtime. Missing/unsafe containment gives mesh-only Rebuild guidance, never direct-process fallback. The supervisor creates only the optional processor tree in a kill-on-close job at process birth, verifies membership before resume, and monitors the exact owning process handle. Binary processor stdin/stdout are separate from authoritative supervisor lifecycle receipts; processor stderr is discarded. Normal child exit also drains descendants.

Stop sends processor Stop plus EOF, permits two seconds of grace, then terminates only its owned job and allows five seconds to verify all processes ended. The panel bounds an unresponsive supervisor and uses read-only exact-identity/job verification if its receipt is lost. Failed verification remains retryable and blocks reuse; it is never labelled Stopped. Owner/supervisor death cannot leave an uncontained processor. No provider/acquisition job or unrelated process is touched. Other platforms need equivalent containment, not a claim that cooperative EOF is crash-safe.

Standalone focused build: `cmake -S native/mesh-supervisor -B <isolated-output> -A x64`, then `cmake --build <isolated-output> --config Release`. Set `XRB_TEST_MESH_SUPERVISOR` to that executable for actual fake-child/grandchild tests. A skipped check is not containment evidence.

## Legacy ownership and lifecycle

The panel starts the contained program directly, with the declared argument array and no shell. Its cwd is the program's directory. Native launch metadata has an optional `handMeshRuntimeJson` with `{version:1,url,token}`; the URL is an ephemeral `http://127.0.0.1:<port>` service and the token is run-owned. This is not part of a portable Hands profile or package. Existing hosts/bundles without this feature remain skeleton-only and show rebuild/relaunch guidance in mesh status. Host input is never gated on it.

The child communicates only over private stdin/stdout pipes, not the renderer's credential. Stderr is drained without forwarding untrusted logs. It MUST exit when stdin closes, including owner crash; subprocesses it owns must do the same. Ready timeout is 10 seconds. Processor readiness does not start the missing-SDK deadline: the panel first completes the owning runner's launch, including up to 30 seconds of dev-server preparation, then allows 30 seconds for the host document/SDK to connect. An independent 90-second unattached-startup cap cleans up even when launch never reaches that notification. None of these waits gates skeleton input. Stop sends `stop` and EOF, waits two seconds, then terminates the owned child; failed termination is reported. Host exit, run rollback, page disposal and panel shutdown retire requests/credentials. A failed processor is not automatically restarted; the next run retries.

## Private pipe packets

All packets have a 12-byte little-endian header: uint32 magic `0x314d5258`, uint32 JSON-control byte length, uint32 binary-payload byte length. UTF-8 JSON follows, then packed little-endian numeric buffers. Control is at most 16 KiB; a whole packet is at most 2 MiB. Stdout contains packets only, no logging. `packages/sdk/src/hand-mesh-protocol.ts` is the reference codec.

- `start`: `{type:"start",version:1,owner,id,settingsVersion,settings,limits,ownerLoss:"exit-on-stdin-end"}`. Validate installed runtime/assets offline; never fetch them implicitly.
- `ready`: `{type:"ready",version:1}` after compatible initialization. A ready child is not proof an app is drawing meshes.
- `frame`: `{type:"frame",epoch,sequence,revision,sentMs,sampleMs,hands:[{id,handedness,keypoints}]}`. At most two hands, each with 21 finite XYZ positions in panel metres. These are copies of the final SDK sampled/adjusted/filtered/predicted pose, not raw acquisition. Handedness is left/right/unknown; a plugin may omit unsupported hands. `sentMs` and `sampleMs` are renderer-clock values, not the child clock. Reset internal state when epoch/revision or a hand identity changes. Do not apply another global size/offset or extra source filtering.
- `result`: echoes `epoch,sequence,revision` and has `meshes:[{id,topology,vertices,normals,indices}]`. Each descriptor's payload is positions (vertices × 3 float32), optional normals (same length), then uint32 indices. Normals is a boolean; indices is an index count divisible by three. Topology is a bounded stable ID/version string. At most 16,384 vertices and 32,768 triangles per hand; all values must be finite and indices within the vertex count. An index count of zero reuses the client's cached matching topology; send full indices on first use/new epoch. No replacement joints or executable draw callback is accepted.
- `stop`: `{type:"stop"}` followed by pipe EOF; dispose and exit. Exit/error/invalid output becomes a classified skeleton-fallback status.

Two mid-detail hands (2,859 vertices and 5,692 triangles each) with positions, normals and full indices are approximately 274 KiB plus the small control header, comfortably under the packet cap. This describes capacity, not a model-performance guarantee.

## Renderer loopback endpoint

The SDK connects once with authenticated `POST /connect`, then sends frames with `POST /frame`; both carry the frame JSON and `Authorization: Bearer <token>`. Exact app/dev origins are checked; preflight permits only POST and the two required headers. `/connect` assigns a consumer epoch and retires the prior one; old frames cannot re-activate it. Credentials never enter URLs, logs or portable output.

A frame may include a bounded `drawingStatus` string so the selector can show actual SDK fallback independently of sidecar readiness. Two seconds without consumer requests stops the optional child, allowing brief page replacement without overlapping consumers. A later disconnected client gets skeleton fallback/relaunch guidance rather than stalled input.

A successful frame response is the binary result packet. HTTP 204 means no usable mesh yet, with an exposed `x-xrb-mesh-status` reason. A superseded newest-pending request is released immediately. The child and SDK paths each hold at most one frame in flight plus one newest pending snapshot. The renderer never awaits a response in its draw/input loop.

Late (over 33 ms from dispatch), malformed, retired-revision/epoch or wrong-hand results are discarded. A previous mesh is drawable only while fresh and within 10 mm maximum keypoint displacement of its associated pose; otherwise draw the ordinary skeleton and show fallback. No detection/hand loss immediately invalidates geometry even during skeleton grace. A physically stuck child gets a two-second frame watchdog, rather than accumulating a FIFO. Keep source confidence separate from fit residuals; this minimum frame contract does not invent confidence.
