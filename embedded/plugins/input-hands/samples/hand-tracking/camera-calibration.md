It cannot manufacture a physical target, move cameras, identify matching real targets for the operator or establish simultaneous exposure from SDK clock labels.

No ID, printed-size, uncertainty or placement fields. ## What is implemented

- Choose each native serial explicitly through the existing single-camera Capture controls. For a fixed target/rig, collect scalar color-camera surface probes sequentially for A and B. No model poses or browser webcam coordinates are used as calibration.
- Fit a proper rigid camera-B→camera-A transform with Horn absolute orientation and a bounded symmetric Jacobi eigensolve. Rotation is **row-major**, translation in metres. `pA = R * pB + t`. The common reference is A's **color optical** frame (+X right, +Y down, +Z forward), not the panel/application frame. No fitted scale, shear, reflection or default identity for B.
- Require at least six distinct, non-collinear, well-spread fit targets, then at least three separate well-spread held-out target pairs for internal spatial qualification. Target XYZ must reproject to its recorded RGB pixel. Show per-target residuals, fit/held-out metric RMS/maximum and bidirectional reprojection RMS.
- Bind both roles to distinct actual serial/profile/intrinsics/extrinsics/geometry fingerprints. Reject another device/profile without explicit Clear/recalibration. SDK metadata identity does **not** detect physical camera movement; the operator must keep the rig fixed and invalidate calibration after movement.
- Bounded local JSON export/import (64 KiB), canonical checksums and signed-zero preservation. Imports recompute the transform and every residual/qualification flag; a forged transform or `fusionEnabled:true` is rejected. No arbitrary image/model/credential extensions are copied into the export.

The output always declares `physicalValidation:"operator-required"`, `temporalAlignment:null`, `fusionEnabled:false`. Passing internal spatial checks is **not** an independent accuracy certificate, exposure synchronization or permission to publish application hands. The separate [fusion workflow](fusion.md) now implements simultaneous two-view capture, bounded paired recording/replay, current-run common-event timing, conservative association, Best View/Fused contributions and identical-input comparison. Those controls require the current profile/rig confirmation and timing in addition to this spatial file. No measured real-rig survey or physical fusion acceptance is claimed.

## Collect actual calibration data

Reuse `http://127.0.0.1:5190/`, or start the viewer:

Use the normal panel's `/hand-tracking/` tool after explicit bundled setup. Optional model/device dependencies need
separate configuration and an explicit Start action; default generated fixtures need neither.

1. Fix both cameras so their views overlap. Use recognizable fiducial centres on a stationary, nonreflective, depth-visible surface; **not a moving hand or model skeleton**. Mark six fit IDs (`p1`…`p6`) and three additional, non-collinear held-out IDs (`p7`…`p9`), spread across the working volume/view. Do not move either camera or the target during the entire A/B survey. A flat board is supported when its targets span two dimensions; a line/tiny cluster is refused.
2. In Capture choose the full native serial for A and Start capture. Hand tracking may be disabled in Settings; the calibration uses depth probes independently of the model. Opening the page or calibration panel never starts acquisition.
3. Click a target centre in the **RGB** preview. Wait for an accepted purple surface probe/current XYZ; holes, edges, stale frames or unqualified RGB/depth pairing cannot be added. In Settings → **Camera-to-camera spatial setup**, choose role A, enter its ID and Fit/Held-out use, then **Add current RGB surface probe**. Repeat all nine IDs. Display mouse/pixel quantization is part of setup uncertainty, not subpixel ground truth.
4. Stop A normally, select B's different native serial, then Start B. Targets already collected remain in memory. Add B's measurements of the **same fixed physical IDs** with matching Fit/Held-out roles. A target/role cannot be silently overwritten; Remove selected target explicitly to replace it.
5. Describe the setup/reference and enter its independently assessed reference/setup uncertainty in metres, or leave unknown. Unknown uncertainty keeps a fit provisional. Confirm fixed cameras/matching static targets, then **Fit spatial transform**.
6. Review each residual and the held-out checks, not only the fitted RMS. Defaults are heuristic acceptance limits: RMS ≤15 mm, maximum residual ≤30 mm, bidirectional reprojection RMS ≤8 pixels. Fits/held-out failures remain provisional with reasons, never silently trimmed or loosened until they pass. These limits are not advertised sensor/hand accuracy. Internal qualification also requires at least three well-spread held-out pairs and known positive reference/setup uncertainty no greater than the RMS acceptance budget.
7. **Export calibration** if needed. Send the local scalar calibration file for review; no photos, raw RGB/depth or hand poses are required by this tool. Keep it private, outside public/source/cloud-synced folders. Clear setup explicitly before importing another. Import opens no camera/model and resets the current physical-setup confirmation. Nothing is applied to the native input provider or viewer coordinates automatically.

One draft lives in tab memory only. Stop/source switch retains explicitly collected target scalars; Clear/dispose drops them and revokes download URLs. No image upload, automatic file save, raw tracking-pose retention or silent camera/model fallback. Export attempts and before-unload warnings are best effort; verify the file on disk and delete exports manually when evaluation ends. Import/file content checks are not authenticity or physical-truth guarantees.

## Current hardware evidence / next gate

A scalar-only native probe opened both discovered D435s concurrently at RGB8 + Z16 640×480/30 using the pinned SDK 2.54.2, without storing imagery/poses. A short initial probe exposed a startup RGB/depth skew of about **1.28 seconds** on one camera. After both streams ran for a two-second warm-up, a second probe received 120 packets per camera at about **29.98 arrivals/s**, with zero additional reported RGB/depth gaps or repeats; per-camera reported RGB/depth skew was about **9.0–9.6 ms**. Both still reported SDK **System Time**. These are brief functional metadata observations, not station soak, shared-exposure proof, frame-perfect capture, IR-interference/hand quality or physical accuracy evidence. Existing conservative reconstruction guards continue to reject bad pairing; no thresholds were relaxed.
