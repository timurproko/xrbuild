# Launcher

Spatial app catalog using the core SDK and the UI Kit app's exported React components. The authored icon is rendered by `src/icon.js`.

`src/main.tsx` owns bootstrap, pagehide and HMR; `src/index.ts` exports `LauncherScene` and `LauncherCard` without starting a runtime or catalog request. Board, Button, Dialog and Label are imported from `@xr-build/ui-kit-app`, aliased to `embedded/projects/core/ui-kit/src/index.ts`; Vite bundles them into Launcher's single SDK-hosted runtime. The card sheets use visual-only Dialogs, preserving the original input policy. Another app can alias this Launcher's `src/index.ts` and render its scene under its own `mountXrbApp` tree. Keep source aliases for the React bridge/UI Kit entry and deduplicate Three, React, React DOM and Fiber as in `vite.config.js`; never import the run entry.

The public entry also exports the plain `uiKitTheme` declaration (`defaultTheme: 'default'`). `LauncherScene` accepts a controlled `theme="chamfer"` prop or inherits a surrounding `UiKitThemeProvider` from UI Kit's app export; without either it uses its declared unchanged Default. Chamfer changes the board, card sheets, controls and applicable text/icon styling, not layout, icons, branding or behavior. Runtime selection preserves control capture, paging/tilt, catalog reconciliation and an accepted launch's deadline/URL. Its manifest explicitly declares consumption of `bundled:ui-kit` and maps that library's Theme parameter to the existing `theme` scene prop. The panel's Components tab autosaves its UI Kit Theme choice in Launcher's own project settings. Managed sessions apply it to the same scene prop without remounting where normal settings writes are allowed; existing bundled-project idle restrictions still apply. Unmanaged packages/publications use their compiled saved settings on next build/start. The runnable entry disposes its read-only settings subscription on pagehide/HMR. This declaration adds no theme selector inside Launcher. See the [app selection guide](../../../../docs/app-components.md#mesh-themes-and-app-defaults).

In a panel preview or a Browser/Desktop development run carrying explicit loopback panel context, the launcher lists eligible active embedded and user apps in sidebar order, excluding itself by logical project identity. An unavailable bound panel shows a library error and is retried without substituting a published library. A published launcher reads its own publisher's inventory and canonical app routes. An external inventory requires explicit `VITE_CATALOG_ORIGIN` (clean HTTPS, or loopback HTTP for development). No production site, user deployment identity or private workspace is built in; a plain dev server does not silently contact a production service.

Build through the selected core's frozen embedded lane. Product source is read-only in ordinary panel use: Rebuild writes to user cache; Copy to workspace creates an independently editable/publication-ready app. The product manifest has desktop/no-input defaults, no publication UUID, package/signing identity or machine settings. Configure those only in the editable copy/user workspace.

Launch actions preserve the SDK's return URL and projection contract. Enter XR is explicit. No camera, native provider or inference runtime starts because this catalog is viewed. The build never scans sibling project repositories or private source. Optional headset packaging uses the separately configured embedded packager and existing user-owned signing material; it never publishes a second web site.
