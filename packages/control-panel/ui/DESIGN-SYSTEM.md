# XR Build UI design system

`design-system.css` is the visual source of truth for XR Build developer tools. `style.css` contains only control-panel product layout and feature-specific presentation.

## Components

- `xrb-app-bar` + `xrb-brand` + `xrb-product-menu`: application shell and product navigation.
- `xrb-section-label`: column/section heading geometry.
- `xrb-card`: bordered surface.
- `xrb-tabs` + `xrb-tab`: tab navigation.
- `xrb-tab-toolbar`: one heading row with tabs left, `.xrb-tab-toolbar-center` contextual filters centered, and `.xrb-tab-toolbar-end` actions right. Only tabs belong in the ARIA tablist; swap filters/actions alongside their panel without duplicating inner toolbars. The center scrolls horizontally when narrow. Activity X clears log/finished jobs; it never closes Activity or stops active work.
- `xrb-glyph-detail`: detail-preserving, theme-specific tint for opaque emoji artwork; silhouette tint would erase internal detail. Settings Apps and the Apps favicon share one emoji identity and the `--xrb-glyph-detail-filter` theme tint.
- Toolbar trailing icon buttons keep their full 28px hit area; optical compensation aligns the visible clear glyph with the leading tab text's edge inset.
- `xrb-focus-inset`: keyboard focus stays inside clipped navigation surfaces. Sticky masks use `--xrb-sticky-mask-gap`, shorter than the heading/card gap, so selected borders remain visible.
- `xrb-sidebar-content` + `xrb-sidebar-section`: consistent tab-panel top spacing, scrolling, scrollbars, and first-section margin reset for tool sidebars.
- Shared controls: buttons, fields, checkboxes, `xrb-switch`, `xrb-toggle-pill`, `xrb-segmented`, `xrb-filter-chip`, `xrb-swatch`, `xrb-tool-button`, `xrb-range`, dialogs and dialog headers/actions, the borderless `xrb-progress-dialog`, the styleable dropdown/listbox component, shared checkbox/checkmark geometry (including multi-select menus), automatically enhanced `xrb-number-control` steppers, `xrb-icon-button` actions, shared SVG icons, and portal tooltips.
- Layout: spacing tokens (`--xrb-space-field`, `--xrb-space-stack`, `--xrb-space-section`) feed `xrb-stack`, `xrb-control-group`, `xrb-button-row`, `xrb-field-grid`, `xrb-toggle-grid`, `xrb-sidebar-content`, and `xrb-sidebar-section`; products should not add margins between component children.
- Reveal motion: `setRevealed()` animates conditional blocks with shared height/fade motion, can resume from an elapsed time after re-rendering, and respects reduced-motion preferences.
- `xrb-help`: secondary helper text. Add `field-error` for validation: inputs and dropdowns keep their normal surface/focus treatment while the helper typography changes to the semantic error color. `enhanceHelpText()` normalizes plain helper copy to a capitalized sentence ending in a period.
- Content: `xrb-supporting-text`, `xrb-code-block`, `xrb-disclosure`, `xrb-section-label`, and `xrb-inline-edit` own repeated supporting copy, readouts, disclosure headings, title dividers, and inline editing.
- Media and data: `xrb-media-stage` + `xrb-media-empty` provide one camera/depth preview frame and no-feed state; `xrb-empty-state` standardizes empty output; `xrb-key-value-list` provides compact label/value columns.
- Shared maintenance: `restartPanelInPlace()` keeps the progress modal and reload on the active tool route instead of navigating to the Control Panel.
- `design-system.js`: `installDropdowns()` for generated `.dropdown` controls, `enhanceSelects()` for native single-selects, `installNumberSteppers()` to enhance every numeric input with shared step controls, `setFieldError()` to place and clear shared validation for inputs/dropdowns, `installTabs()` for the animated shared tab indicator, `iconSvg()` / `installIcons()` for shared icons, `positionFloating()` / `openFloating()` for bounded menus and their initial focus, `resumeAnimations()` for resumed component motion, `installTooltips()` for unclipped custom tooltips, and `enhanceHelpText()` for shared helper copy.
- Tooltip hints: use `data-tooltip` for explicit copy. `installTooltips()` also migrates legacy HTML `title` hints (including inserted nodes and updated status text) to `data-xrb-tooltip-title`, preventing native tooltip popups. Explicit copy wins over migrated detailed help, which wins over a short button/link `aria-label`. Disabled controls and swatches participate; iframe titles and the document title retain their semantics. Visible tooltips extend `aria-describedby` without replacing existing descriptions and use the top layer over dialogs when supported. Plain text actions without hints remain tooltip-free. Mount once per document and dispose listeners/observers on teardown.
- Shared state/menu classes: `state`, `chip`, `menu`, `toggle`, `row`, `spacer`, `muted`, `mono`.
- Dropdown status marks and details: a generated `.dropdown` may carry `data-marks` (a JSON map from option value to `ok`, `warn` or `err`) and `data-details` (a map from option value to secondary text); each marked option and the closed button then show the shared `xrb-status-dot` before the label, and the detail follows the label as smaller muted `xrb-option-detail` text. The Publisher field marks destinations that are published (green) or deployed but unreachable (amber); Live version marks the verified live release and shows when each release was created.
- Version controls: one shared `#version-menu` (Patch/Minor/Major with the resulting version beside each item) serves every version input; the input's context menu (mouse right-click or the keyboard context-menu key) opens it through `openFloating`, which focuses the first item, and `menuKeyboard` handles arrows and Escape. Package version and publication Next version share this behavior; the menu edits only the draft. The publication row places Live version before Next version. Every workflow surface puts its primary action (Run/Stop, Publish/Update with the confirmed Unpublish, Build) left-aligned in a `project-actions` row below all of its content, while Folder and Open JSON stay at the identity row's right edge. On Publish only, an icon link (the shared `open` icon) precedes JSON and opens the version chosen in Live version: an inspected release's archive, published or not, otherwise the selected destination's live app whenever it is reachable.
- Live version dropdown: the shared dropdown lists every retained release newest first (version or `Legacy (unversioned)`, creation time as detail text), marks the verified live release green and a merely requested one amber, and selects the live one. Choosing another release inspects it: Preview opens its archive and Activate asks "Activate <version> version?" through the shared dialog, explaining in plain words what replaces what; choosing the live (or Not live) entry again ends the inspection. Without history it is a read-only field (`Not live`, `Legacy (unversioned)`, `Not verified yet`).

Legacy control-panel class names remain aliases while markup migrates. New workspace tools should use the `xrb-*` names, mount shared interactive components, and add only product-specific layout CSS. Load IBM Plex Sans/Mono and `design-system.css` before product CSS and application modules to avoid type/layout flashes.

Do not copy tokens or component rules into a tool. Product styles may position a shared component in feature layout, but may not redraw its surface, typography, states, icons, animation, or interaction. Small differences belong in an `xrb-*` modifier variant. If a shared visual changes, change the design system and verify both the control panel and tools.
